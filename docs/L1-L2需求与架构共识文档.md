- 状态：已实现，自动验证完成，待人工发布验收
- 适用版本：easyT 2.1.0 及后续兼容版本
- 实现审计：`42cc000` 及 AUD-001/AUD-002 后续修复（2026-08-10）

## 1. 文档目的

本文记录 easyT 翻译缓存的最终需求与架构共识，是后续实现、代码审查和验收的依据。本文不是建议清单；除非形成新的明确决策，文中的“必须”“不得”和固定数值均为约束。

本文最初用于冻结实施范围；截至 `42cc000`，对应 Rust、TypeScript、数据库和界面实现已经完成。规范性约束仍作为代码审查与回归验收依据。

### 1.1 实现审计结论

- `42cc000` 审计发现的 2 项 L2 错误状态/内部统计偏差已经修复；当前实现符合本文的 L1/L2、缓存键、Use/Refresh/Bypass、容量、恢复、清除、统计、隐私和 UI 行为约束，详见 SDD 0.4 的实现审计表。
- L2 worker 仍由唯一命名线程独占 SQLite Connection；为可靠执行 30 秒 Touch 定时 flush，线程内部使用单线程 Tokio runtime 与异步 `recv`，不在应用 Tokio core 上执行 SQLite。
- 清除二次确认使用应用内自适应 `alertdialog`，窄屏下限制视口高度、允许纵向滚动并让按钮自动换行；该实现保持二次确认、键盘关闭、焦点和文案合同。
- 修复后 Rust 172 项、Vitest 46 项测试与 Rust clippy/format 检查通过，证据记录在 `docs/translation-cache/issues/07-verify-release-translation-cache.md`。真实 Qwen/Official API 凭证 E2E 尚未执行；用户已明确不要求重跑安装包构建。

## 2. 目标与非目标

### 2.1 目标

- 对高频短词、重复段落以及包含 Markdown/LaTeX 的重复原文提供近乎即时的本机命中。
- 使用 L1 内存缓存降低进程内重复查询延迟，使用 L2 SQLite 缓存跨启动复用完整译文。
- 缓存故障时无条件降级到现有翻译后端，不改变翻译成功与失败语义。
- 控制内存和磁盘上限，依靠版本失效与容量 LRU 淘汰长期运行。
- 保持 `TranslationBackend` 为 Official API 与 WebGateway 的统一入口。
- 为用户提供可见、可清除且不与译文内容混合的缓存反馈。

### 2.2 非目标

- 不缓存 SSE 增量、推理内容、Future、请求句柄或未完成译文。
- 不实现相似文本、语义、模糊或分段缓存。
- 不新增请求代次；现有 latest-wins 仍是唯一并发控制者。
- 不按供应商、模型、账号或请求入口隔离缓存。
- 不设 TTL，不提供 L1/L2 开关或容量设置。
- 不做 in-flight 请求合并。
- 不承诺取证级安全擦除。

## 3. 领域术语

- **翻译缓存**：由 L1 与 L2 构成、只保存完整成功译文的本机加速模块。
- **L1**：进程内加权 LRU 缓存，退出后消失。
- **L2**：位于 `easyT_Data` 的 SQLite 持久化缓存。
- **Use**：按 L1、L2、翻译后端顺序查询的普通策略。
- **Refresh**：绕过缓存读取，以当前模型重新翻译，成功后覆盖共享缓存。
- **Bypass**：完全不读、不写缓存的内部策略。
- **缓存 epoch**：清除使用的单调递增代次，用于拒绝迟到写入。
- **逻辑大小**：用于单条和总容量管理的稳定估算值，不等同于 SQLite 实际文件大小。

## 4. 固定架构

缓存是 `translation_backend` 内的深模块：

```text
src-tauri/src/translation_backend/
├── cache/
│   ├── mod.rs              # TranslationCache：唯一外部入口
│   ├── key.rs              # 规范化、CacheKey、版本常量
│   ├── entry.rs            # CacheEntry、CacheStatus、统计
│   ├── memory.rs           # L1 加权 LRU
│   └── persistent.rs       # L2 worker 与 SQLite
├── official_api/
├── web_gateway/
└── mod.rs                  # TranslationBackend 路由与缓存编排
```

`TranslationBackend` 继续作为翻译能力的唯一 seam。Official API Adapter 和 WebGateway Adapter 不得知道缓存存在，也不得各自实现缓存。Tauri Command 不判断 Qwen、Official API 或具体缓存层。

缓存外部接口保持小而稳定，概念上只暴露：

```text
lookup(key, epoch)
store(key, result, epoch)
clear()
stats()
shutdown()
```

实现不得把 SQLite、L1 分池或供应商细节泄漏给调用者。

## 5. 请求路径与策略

### 5.1 Use

全局快捷键（默认 `Ctrl+T`）和手动输入普通翻译传 `forceRefresh=false`：

```text
校验输入
  → 生成版本化 CacheKey
  → 查询 L1
  → 未命中时在 50 ms 预算内查询 L2
  → 仍未命中时请求翻译后端
  → 仅完整、成功、非空且未超限的结果写入 L1
  → 异步写入 L2
  → 返回译文
```

L2 命中必须提升到 L1。缓存命中直接返回完整结果；即使开启流式输出，也不模拟增量事件。

### 5.2 Refresh

右上角“重新翻译”和错误态“重试”传 `forceRefresh=true`：

- 绕过 L1/L2 读取。
- 使用当前翻译后端、供应商和模型发起网络请求。
- 完整成功后全局覆盖同一缓存键，先写 L1，再异步 UPSERT 到 L2。
- 网络失败不得覆盖或删除旧缓存，也不得静默把旧译文当成本次成功。
- 若页面原本显示旧缓存译文，则保留它并显示“重新翻译失败，当前仍显示此前的本机缓存译文。”，允许再次重试。
- 若没有旧缓存译文，则按普通翻译失败展示。

### 5.3 Bypass

Bypass 是 Rust 内部策略，前端不得直接选择。测试连接、`saveHistory=true` 的 Qwen 请求和诊断请求固定使用 Bypass。Bypass 不读写缓存，也不进入公开命中率。

### 5.4 契约

前端只传 `forceRefresh: boolean`。Command 将 false 映射为 Use、true 映射为 Refresh；`TranslationBackend` 决定实际策略，Adapter 不接收缓存策略。

Adapter 仍返回 `BackendResult`；`TranslationBackend` 返回：

```text
TranslationOutcome {
  result: BackendResult,
  cache_status: CacheStatus
}

CacheStatus = Miss | MemoryHit | PersistentHit | Refreshed | Bypassed
```

Tauri 至少返回 `translatedText` 与 `fromCache`。只有 MemoryHit/PersistentHit 映射为 true，前端无需知道具体缓存层。

## 6. 缓存键与规范化

### 6.1 共享边界

所有翻译后端、供应商、模型和账号共享同一缓存。backend、provider、base URL、model、账号、设备标识、请求入口、流式开关、超时和网页历史开关均不得进入键。

`BackendSource` 作为来源元数据保存但不影响匹配。切换模型或供应商后，Use 可以返回旧模型产生的共享缓存；需要当前模型结果时使用 Refresh。

### 6.2 键材料

使用 BLAKE3 256-bit，按固定顺序哈希：

1. 固定 domain：UTF-8 `easyT.translation-cache`。
2. `cache_key_version`。
3. `prompt_version`。
4. 规范化原文的字节长度与 UTF-8 字节。
5. trim 后目标语言的字节长度与 UTF-8 字节。
6. 会实质改变译文的应用级输出参数，按稳定字段编号、长度前缀和固定顺序编码。

变长字段必须带长度前缀，整数使用文档化的固定宽度与字节序。32 字节摘要作为 L1/L2 主键。数据库不保存原文，也不做哈希碰撞后的原文二次比较。

当前键只含版本、规范化原文和目标语言。未来新增“正式/口语”“术语表”“特定格式”等影响输出的选项时，必须加入键或提升 `cache_key_version`。仅 prompt 改变时提升 `prompt_version`。

### 6.3 输入规范化

单行文本：

- 移除开头 BOM。
- 移除首尾 Unicode whitespace。
- 保留内部空白和大小写。

多行文本：

- 移除开头 BOM。
- CRLF 和 CR 统一为 LF。
- 保留首尾空白、缩进和空行。

任何文本都不得小写化、折叠空格、执行 NFC/NFKC、修改 Markdown、反斜杠、代码块或 LaTeX。目标语言只执行 trim。

## 7. 可缓存结果与大小

仅完整成功、译文非空、非 Bypass、epoch 有效且逻辑大小不超过 1 MiB 的结果可缓存。取消、超时、网络中断、协议不匹配、部分回答、SSE delta、reasoning 和空结果不得缓存。

```text
logical_size_bytes =
    32
  + normalized_source_text_bytes
  + target_language_bytes
  + translated_text_bytes
  + source_backend_bytes
  + source_provider_bytes
  + source_model_bytes
  + 256
```

全部字符串按 UTF-8 字节计算。规范化原文预估已超过 1 MiB 时直接跳过缓存查询；翻译后按完整公式再判断。大于 1 MiB 不缓存，等于 1 MiB 允许。超限请求正常翻译，计入内部 `oversized_bypasses`，不进入公开命中率。

## 8. L1 内存缓存

固定限制：

- 总逻辑容量 10 MiB，总条目 1,024，单条 1 MiB。
- 短文本：规范化 UTF-8 原文不超过 256 字节且不含 LF；最多 768 条；无长文本时可使用接近全部 10 MiB。
- 长文本：最多 256 条，最多 7 MiB。

使用两个 `lru::LruCache`，不手写链表。一个 `MemoryCacheState` 和一个 `std::sync::Mutex` 原子维护两池、总/长文本字节、`access_tick` 与 epoch。锁内不得 await、I/O、大对象序列化或复制译文；值使用不可变共享所有权。Mutex poisoning 时脱敏告警并恢复，不得让翻译失败。

插入固定顺序：

1. 同键存在时先删除旧值和计量。
2. 插入对应分池。
3. 先执行分池条数与长文本 7 MiB 限制。
4. 再执行全局 10 MiB 与 1,024 条限制。
5. 全局超限时比较两池 LRU 尾部 `access_tick`，淘汰全局最旧项；相同 tick 用缓存键稳定排序。

L1 淘汰不得删除 L2。L2 提升 L1 时必须重新检查 epoch 并执行相同容量规则。

## 9. L2 持久化缓存

### 9.1 引擎与限制

- 固定 `rusqlite + bundled SQLite`。
- 路径：`easyT_Data/cache/translation_cache.sqlite3`。
- 最大逻辑容量 256 MiB，最大条目 50,000，单条 1 MiB。
- 任一上限超出时淘汰至不超过 230.4 MiB 且不超过 45,000 条。
- 每批最多删除 500 条，循环至同时达到低水位。
- 不设 TTL，只按版本不可达和容量 LRU 淘汰。
- release 体积预计增加约 1.01 MiB，该成本已接受。

### 9.2 单 worker

唯一 `PersistentCacheWorker` 线程独占唯一 SQLite Connection，不使用 `Mutex<Connection>`，不在 Tokio core 执行 SQLite。

- 线程名 `easyT-cache-db`，栈 512 KiB。
- 有界命令队列容量 512。
- 命令：Lookup、Store、Touch、Clear、Stats、Shutdown。
- 状态：Starting、Ready、Degraded、Stopped。
- 数据库异步初始化，不阻塞主窗口；Starting 时允许跳过 L2。
- 普通 Lookup/Store/Touch 使用非阻塞 try_send，队列满则跳过。
- Clear/Shutdown 可靠入队并允许有限等待。
- Store/Touch 携带 epoch；SQLite 执行前拒绝旧 epoch。

### 9.3 查询、写入与 Touch

L2 Lookup 从成功入队起预算 50 ms。worker 未就绪、队列满或超时都立即走网络；迟到结果丢弃。超时/错误增加 `lookup_failures`，当前 Use 请求仍计为 miss。

翻译成功后同步写 L1、异步 write-behind 到 L2，展示不等待磁盘。L2 写失败不回滚 L1。相同键 UPSERT 完整替换译文、来源和元数据。

L1/L2 命中均更新访问时间与命中数。Touch 按键合并，并在下列时机 flush：

- 每 30 秒。
- 累积 256 个不同键。
- 淘汰、清除或关闭前。

崩溃允许丢失最近 30 秒统计。淘汰稳定排序：

```sql
ORDER BY last_accessed_at_ms ASC, generated_at_ms ASC, cache_key ASC
```

### 9.4 SQLite 配置

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA page_size = 4096;
PRAGMA cache_size = -2048;
PRAGMA busy_timeout = 2000;
PRAGMA wal_autocheckpoint = 1000;
PRAGMA auto_vacuum = INCREMENTAL;
```

新库在建表前设置 page size 与 auto-vacuum。WAL 超过 16 MiB或容量淘汰后执行被动 checkpoint。普通淘汰不得执行完整 VACUUM。

## 10. SQLite 表结构

初始 `PRAGMA user_version = 1`。时间为 Unix epoch 毫秒，大小为字节。

```sql
CREATE TABLE cache_entries (
    cache_key               BLOB    PRIMARY KEY NOT NULL CHECK(length(cache_key) = 32),
    cache_key_version       INTEGER NOT NULL,
    prompt_version          INTEGER NOT NULL,
    target_language         TEXT    NOT NULL,
    translated_text         TEXT    NOT NULL,
    source_backend          TEXT    NOT NULL,
    source_provider         TEXT    NOT NULL,
    source_model            TEXT    NOT NULL,
    generated_at_ms         INTEGER NOT NULL,
    last_accessed_at_ms     INTEGER NOT NULL,
    hit_count               INTEGER NOT NULL DEFAULT 0 CHECK(hit_count >= 0),
    source_text_bytes       INTEGER NOT NULL CHECK(source_text_bytes >= 0),
    translated_text_bytes   INTEGER NOT NULL CHECK(translated_text_bytes >= 0),
    logical_size_bytes      INTEGER NOT NULL CHECK(logical_size_bytes >= 0)
) WITHOUT ROWID;

CREATE INDEX idx_cache_entries_lru
ON cache_entries(last_accessed_at_ms, generated_at_ms, cache_key);

CREATE INDEX idx_cache_entries_prompt_version
ON cache_entries(prompt_version);

CREATE TABLE cache_stats (
    id                   INTEGER PRIMARY KEY CHECK(id = 1),
    l1_hits              INTEGER NOT NULL DEFAULT 0,
    l2_hits              INTEGER NOT NULL DEFAULT 0,
    misses               INTEGER NOT NULL DEFAULT 0,
    bypasses             INTEGER NOT NULL DEFAULT 0,
    refreshes            INTEGER NOT NULL DEFAULT 0,
    oversized_bypasses   INTEGER NOT NULL DEFAULT 0,
    lookup_failures      INTEGER NOT NULL DEFAULT 0,
    store_failures       INTEGER NOT NULL DEFAULT 0,
    touch_failures       INTEGER NOT NULL DEFAULT 0,
    last_cleared_at_ms   INTEGER
);

INSERT INTO cache_stats(id) VALUES (1);
```

统计经 worker 批量持久化并跨重启保留，直至清除。

迁移使用 `PRAGMA user_version`，只允许顺序事务迁移。版本过新、迁移失败、CORRUPT、NOTADB 或 schema 不兼容时关闭连接，按时间戳隔离主库/WAL/SHM并创建新库。最多保留一组隔离文件，新组替换旧组。隔离和日志不得包含原文、译文或凭证；清除同时删除隔离文件。

## 11. 错误与恢复

缓存是 best-effort 加速器。任何初始化、查询、写入、Touch、迁移、锁、I/O 或损坏错误都不得把成功翻译变成失败。

- BUSY、LOCKED、临时 I/O、队列满、查询超时：当前请求走网络，worker 保持 Ready。
- 单行字段非法：删除该行，按 miss 处理。
- CORRUPT、NOTADB、schema/迁移错误：隔离并重建；失败进入 Degraded。
- 权限、磁盘或初始化永久错误：进入 Degraded，本次运行不循环重试，L1 继续工作。
- Degraded 时详情显示“持久化缓存不可用”，按钮改为“重建持久化缓存”。
- 用户重建成功回 Ready；失败显示缓存操作错误；下次启动重新尝试初始化。
- 只有显式清除、重建和统计操作向用户返回缓存错误；普通翻译不弹缓存错误。

## 12. 清除、epoch 与关闭

“清除翻译缓存”清除 L1、L2 主库/WAL/SHM、隔离文件、待处理 Store/Touch、合并 Touch 和全部统计。

固定流程：

1. 原子增加 epoch。
2. 同一 L1 锁内清空 L1 与进程内统计。
3. worker 拒绝旧 epoch 命令。
4. 关闭 SQLite Connection。
5. 删除主库、WAL、SHM 和隔离文件。
6. 创建新库、schema 和空统计。
7. 完成后才报告成功。

不得用 `DELETE + VACUUM`。清除失败时 L1 保持为空，L2 进入 Degraded，正常翻译继续。

清除不取消正在翻译的请求。清除前请求可以继续展示结果，但旧 epoch 禁止写回。当前页面原文和译文不清空；成功后移除缓存来源提示，不自动翻译。

应用退出最多等待 1 秒 flush Touch/已入队 Store、尝试 WAL checkpoint 并关闭 Connection；超时允许退出。

## 13. 用户界面

设置页只增加一行：

```text
翻译缓存
本地保存已完成译文，以加快重复翻译
[查看缓存详情]
```

按钮打开模态弹窗，不新增路由。弹窗显示：

- L2 条目数。
- 主库、WAL、SHM 实际占用 / 256 MB。
- 公开命中率。
- 缓存绝对路径。
- 本机存储说明。
- 关闭和清除按钮；Degraded 时为“重建持久化缓存”。

清除必须二次确认，执行期间禁用按钮并显示 loading；成功后统计归零。确认文案说明不会删除设置、Qwen 登录状态或网页对话记录。

公开命中率：

```text
(L1 hits + L2 hits) / (L1 hits + L2 hits + misses)
```

分母为零显示“—”。Refresh、Bypass、超限和内部失败不参与。弹窗条目数仅为 L2；磁盘占用是 main+wal+shm 实际大小。

缓存命中时，在 `OriginalTextPanel` 与 `TranslationPanel` 之间显示独立提示：

> 此译文来自本机缓存，点击“重新翻译”可使用当前模型刷新。

提示不属于译文，不传入 Markdown/KaTeX，不参与复制、字数或持久化；新请求开始时清除旧来源状态，Refresh 成功或清除成功后隐藏。

Refresh 失败且原本显示缓存译文时，保留旧译文和来源提示，并另行显示失败说明，不能让用户误认旧译文来自当前模型。

## 14. 隐私

- L2 明文保存完整译文，不加密。
- 不保存原文，只保存 BLAKE3 键和原文字节数。
- 来源元数据可保存 backend/provider/model。
- 不保存 API Key、Cookie、Authorization、Qwen ticket、设备标识、请求正文或完整响应。
- 不创建额外缓存日志或备份。
- 隔离库可能包含译文，必须纳入清除。
- 界面明确缓存只在本机。
- 清除不是存储介质安全擦除。

## 15. 并发不变量

- latest-wins 仍由现有 `TranslationRequestManager` 唯一负责。
- 缓存不实现 generation，也不改变旧请求不能覆盖新界面的规则。
- abort 请求不得写未完成结果；完整结果写入仍检查 epoch。
- epoch 比较与 L1 条件插入在同一把锁内。
- 每个请求使用独立 SSE decoder，缓存不复用 decoder。
- 本期不做相同键的 in-flight coalescing。

## 16. 验收标准

### 16.1 功能

- 同一规范化原文和目标语言首次成功后，第二次 Use 命中。
- 重启后从 L2 命中并提升 L1。
- 切换供应商/模型后 Use 仍命中，Refresh 使用当前模型覆盖。
- saveHistory、测试连接和诊断请求不读写缓存。
- Markdown、代码块、公式、反斜杠、空行和缩进往返字节不变。
- 流式中断、取消、超时、空结果和部分回答不产生缓存项。
- 超过 1 MiB 正常翻译但不缓存。

### 16.2 容量与故障

- L1 不超过 10 MiB/1,024 条；长文本不超过 7 MiB/256 条；短文本不超过 768 条。
- L2 超过 256 MiB 或 50,000 条后降至 230.4 MiB 且 45,000 条以内。
- 普通淘汰不执行完整 VACUUM。
- 清除期间完成的旧请求不回填。
- L2 超时、队列满、SQLite busy/locked、损坏或不可写时仍请求翻译后端。
- L2 Store 失败不撤销译文或 L1。
- 应用退出等待缓存不超过 1 秒。

### 16.3 界面

- 详情通过设置页按钮打开弹窗，不直接铺开统计。
- 清除需要确认，执行中不可重复点击，成功后归零。
- 缓存提示位于原文和译文之间，不进入复制或 Markdown/KaTeX。
- Refresh 失败不覆盖旧缓存，也不把旧译文标为当前模型的新结果。

## 17. 测试分层

- `key.rs`：BOM、换行、Unicode 空白、Markdown/LaTeX、长度前缀、版本、稳定 BLAKE3 向量。
- `memory.rs`：短/长分类、替换计量、容量、确定性 LRU、epoch 竞态。
- `persistent.rs`：schema、迁移、UPSERT、Touch 合并、淘汰、WAL、隔离、50 ms 超时、Degraded。
- `TranslationBackend`：Use/Refresh/Bypass、完整/部分结果、跨模型共享、取消。
- Command：`forceRefresh`、`fromCache`、统计和清除错误。
- 前端：提示隔离、复制、Refresh 失败保留旧译文、清除后状态、详情弹窗。
- 手工：真实 Qwen/Official API 的首次请求、命中、切换模型、刷新、重启和清除。

## 18. 已接受的权衡

- bundled SQLite 约增加 1.01 MiB release 体积，换取可靠查询、事务、迁移和容量管理。
- 跨模型共享提高命中率；通过缓存提示和 Refresh 保留用户控制权。
- 明文保存译文降低复杂度，但要求本机说明、敏感日志过滤和显式清除。
- 50 ms L2 预算可能把潜在命中降级为网络请求，优先避免缓存放大等待。
- 不设 TTL，依靠 prompt/key 版本与容量 LRU 管理陈旧数据。
