## 1. 背景与问题

easyT 当前的 Qwen 网页实验模式只管理一个登录身份：一个 `QwenSession`、一个明文凭证文件和一个 WebView2 profile。设置页只能查看单一登录状态，所有 Qwen 翻译和连接测试都使用同一账号。

目标能力是让用户管理多个独立 Qwen 登录身份，并在健康、已登录且已启用的账号之间，为每次真实 Qwen 翻译尝试执行稳定的 Round Robin。该能力服务于多个合法账号的本地管理和请求分配，不用于绕过 Qwen 的限流、配额、访问控制或风控。

多账号调度是 WebGateway 内部资源管理能力，不改变翻译结果语义。远端身份、账号名称和凭证不得泄漏到共享缓存、翻译历史、译文、进度事件或普通用户日志。

## 2. 目标

- 支持最多 10 个本地 Qwen 账号槽位。
- 每个账号独立保存凭证、浏览器 profile、登录状态和健康状态。
- 在健康、已登录、已启用且空闲的账号之间按用户可见顺序 Round Robin。
- 每次真实 Qwen 翻译尝试选择一次账号；正式重试也重新轮询。
- 使用真实轻量请求复检发生错误的账号，不做定时批量主动探测。
- 为普通故障提供五分钟冷却与按需恢复，为 401/403 提供明确的重新登录路径。
- 保留现有翻译超时、latest-wins、流式输出、缓存、翻译历史和错误安全边界。
- 保留设置页全局“测试连接”，并增加逐账号测试。
- 为账号池、登录、存储和 Qwen 请求错误提供稳定、结构化、用户可见的具体错误码。
- 从现有单账号数据无感迁移，不丢失凭证或浏览器 profile。
- 不新增前端 UI dependency，不扩大远程 Qwen WebView 的 Tauri capability。

## 3. 非目标

第一版不包含：

- 通过账号轮换绕过 Qwen 限流、配额、访问控制或风控。
- 用户选择加权、随机、最少连接或其他调度算法。
- 自动读取 Qwen 邮箱、昵称、手机号或稳定远端用户 ID。
- 检测多个本地账号槽位是否登录了同一个 Qwen 身份。
- 主动批量健康检查、定时向全部账号发送请求或后台保活。
- 流式输出中断后的正式重试或跨账号续传。
- 超出现有范围的网络错误、超时或认证错误正式重试。
- 自动回退到 Official API。
- 账号请求量、成功率、配额、用量、成本或性能报表。
- 账号导入导出、云同步、共享或跨设备同步。
- 凭证加密或 Windows Credential Manager 迁移。
- 按账号隔离翻译缓存或在翻译历史中记录账号。
- 改变 Qwen 私有请求协议、Prompt、模型允许列表或保存网页历史的用户开关。
- 术语表功能。

## 4. Canonical 术语

本文继承根 `CONTEXT.md` 中的翻译领域术语，并重点使用：

**Qwen 账号**<br>
用户管理的一个本地账号槽位及其独立 Qwen 登录身份。账号 ID 是 easyT 生成的本地 UUID；本地名称只是用户标签，不代表远端真实身份。

**Qwen 账号池**<br>
全部本地 Qwen 账号的集合。属于账号池不代表当前可参与账号轮询。

**健康 Qwen 账号**<br>
已启用、已登录、凭证可读取、未登录过期、不在冷却或待验证状态，且当前空闲的账号。

**账号轮询**<br>
按设置页显示顺序，从当前游标开始为真实 Qwen 翻译尝试选择账号的 Round Robin 策略。

**正式翻译尝试**<br>
为完成用户的一次翻译请求而真实发送到 Qwen 的一次请求。现有一次性输出的 429/5xx 重试属于新的正式翻译尝试。

**账号复检**<br>
固定使用指定账号发送的一次真实轻量翻译，用于更新账号健康状态。它不是正式翻译重试，输出不能作为用户译文，也不推进账号轮询游标；一次性输出中的同步复检会占用原请求剩余总超时。

**待验证 Qwen 账号**<br>
已结束冷却，或因原翻译请求总超时耗尽而无法完成复检，再次参与正式翻译前必须先通过账号复检的账号。应用退出中断复检时保留复检前健康状态，不因此转为待验证。

**账号占用**<br>
一个账号正在执行正式翻译尝试、账号复检、全局测试或逐账号测试。账号占用期间不能再承担另一项 Qwen 网络操作。

## 5. 核心产品模型

### 5.1 账号身份与上限

每个账号包含：

```text
QwenAccount
├── accountId：本地 UUID，稳定身份
├── displayName：用户填写的本地名称
├── enabled：是否启用
├── order：用户可见顺序
├── loginState：未登录 / 登录中 / 已登录 / 登录过期
├── lastHealth：健康 / 不健康
├── runtimeHealth：健康 / 冷却中 / 待验证
└── occupancy：空闲 / 使用中
```

规则：

- 最多存在 10 个账号槽位；停用、未登录和过期账号均计入上限。
- 达到上限时禁用“添加账号”，提示用户先删除账号。
- `accountId` 不使用账号名称、Cookie、ticket、邮箱或其哈希。
- 名称去除首尾空白后必须为 1 至 40 个 Unicode 字符。
- 名称允许重复，禁止 NUL 和控制字符。
- 名称只在本机展示，不发送给 Qwen，不写入翻译历史或普通请求日志。
- easyT 不主动识别或阻止两个槽位登录相同远端身份。

### 5.2 可参与轮询的条件

账号同时满足以下条件才可直接参与正式翻译：

- 已启用。
- 登录状态为已登录。
- 本地凭证存在、格式有效且可读取。
- 最后健康判定为健康。
- 不在冷却中。
- 不是待验证账号。
- 当前未被正式翻译、复检或测试占用。

登录中、未登录、登录过期、停用、冷却中、待验证和使用中的账号仍属于账号池，但调度行为不同。

### 5.3 设置页状态

账号行只显示以下稳定状态：

| 状态 | 含义 |
|---|---|
| 已停用 | 用户关闭启用开关，不参与轮询 |
| 未登录 | 没有可用本地凭证 |
| 登录中 | 当前账号处于唯一登录流程 |
| 可用 | 已登录、启用、健康且空闲 |
| 使用中 | 正在执行正式尝试、复检或测试 |
| 冷却中 | 复检失败后的五分钟排除期，显示剩余时间 |
| 待验证 | 冷却结束或未能完成复检，使用前必须复检 |
| 登录过期 | 收到 401/403，必须重新登录 |

状态展示采用确定性优先级，避免同时显示多个互相冲突的主状态。第一版不显示请求次数、成功率、错误次数、ticket、Cookie、邮箱或远端真实身份。

## 6. 账号生命周期

### 6.1 添加账号

添加流程固定为：

1. 用户点击“添加账号”。
2. 用户输入符合规则的本地名称。
3. easyT 创建默认启用、未登录的账号槽位和独立账号目录。
4. 账号追加到显示顺序末尾。
5. 目录初始化成功后立即打开该账号登录窗口。
6. 用户取消或登录失败时保留未登录账号，允许稍后重试或删除。

如果账号槽位或 profile 初始化失败，不得打开无归属的登录窗口。

### 6.2 登录与重新登录

- 全局同一时间最多一个账号处于登录或重新登录流程。
- 登录流程不暂停其他已登录账号的正式翻译。
- 每个账号使用自己的 WebView2 profile。
- 登录窗口和 watcher 必须绑定明确的 `accountId`。
- 登录成功后原子保存新凭证，账号进入已登录、健康状态；不额外发送测试请求。
- 重新登录时，在新凭证成功持久化前保留旧凭证和登录前状态。
- 重新登录取消或失败时恢复登录前状态；原本过期的账号仍为登录过期。
- 用户关闭登录窗口或登录超时不得删除旧凭证。
- 登录中账号不能再次开始登录。
- 其他账号尝试登录时返回“登录流程已占用”的稳定错误。

### 6.3 启用、停用与顺序

- 设置页使用启用开关控制账号是否参与后续调度。
- 停用立即阻止后续选择，不取消已经发出的请求。
- 停用不改变凭证、登录状态或最后健康判定。
- 重新启用后恢复停用前状态：原本健康则可用，原本不健康或待验证则仍需复检。
- 停用期间不运行冷却计时 UI；重新启用时若原冷却截止时间已经过去，则进入待验证。
- 用户通过上移、下移调整账号顺序，不引入拖拽依赖。
- 新账号追加到末尾；重命名、停用和重新启用不改变位置。

### 6.4 忙碌期间的管理操作

账号被占用时：

- 允许重命名。
- 允许停用；只影响后续选择。
- 禁止重新登录、退出登录和删除。
- 逐账号测试立即返回“账号正在使用中”。

这条规则覆盖早期“删除后延迟清理”的候选方案：首版不允许在账号忙碌时开始删除。

### 6.5 退出登录与删除

**退出登录**：

- 使用 `ConfirmDialog` 二次确认。
- 删除该账号凭证和整个独立浏览器 profile。
- 保留账号 ID、名称、启用状态和显示顺序。
- 账号进入未登录状态。
- 再次登录创建全新 profile，避免残留 Cookie 恢复旧身份。

**删除账号**：

- 使用 `ConfirmDialog` 二次确认。
- 永久删除凭证、profile、账号目录和注册表条目。
- 不删除或修改共享翻译缓存、翻译历史和 Qwen 远端对话记录。
- 删除失败不得伪装成功；未完成清理的目录必须可诊断和重试。

## 7. 持久化与目录

### 7.1 Canonical 目录

```text
easyT_Data/web_gateway/qwen/
├── accounts.json
└── accounts/
    └── <account-id>/
        ├── credentials.bin
        └── profile/
```

- `accounts.json` 是账号注册表，不放入 `config.json` 或 `AppConfig`。
- 每个账号的凭证和浏览器 profile 必须位于同一个独立账号目录。
- `credentials.bin` 继续沿用当前用户已批准的 UTF-8 明文持久化方式。
- 注册表不得包含 ticket、Cookie、Header、远端身份或凭证派生值。
- 账号目录名只使用本地 UUID，不使用用户名称。

### 7.2 注册表内容

注册表至少持久化：

- schema version。
- 账号 ID。
- 本地名称。
- 启用状态。
- 显示顺序。
- 登录过期状态。
- 最后一次健康判定。

注册表不持久化：

- 轮询游标。
- 使用中状态。
- 冷却截止时间或剩余时长。
- 登录 watcher 运行状态。
- 当前请求、测试或复检信息。

注册表和凭证替换必须使用原子写入。日志不得输出注册表完整正文。

### 7.3 应用启动恢复

- 已启用、凭证格式有效且最后健康判定为健康的账号，启动后直接视为健康，不主动测试。
- 最后健康判定为不健康的账号，启动后进入待验证；不恢复旧冷却计时。
- 登录过期状态跨重启保留，必须重新登录。
- 普通冷却、占用状态和轮询游标在重启后清除。
- 轮询从显示顺序中的第一个可选账号开始。
- 凭证损坏不能被当作已登录或健康。

### 7.4 现有单账号迁移

现有路径：

```text
easyT_Data/web_gateway/qwen/credentials.bin
easyT_Data/web_gateway/qwen/profile/
```

首次升级迁移规则：

1. 检测旧凭证或 profile。
2. 创建包含本地 UUID、源路径、staging 路径、目标路径和迁移阶段的持久化 migration journal。
3. journal 至少区分 `prepared`、`credentialsStaged`、`profileStaged`、`directoryPublished` 和 `registryCommitted`；每完成一个边界就原子更新并刷新 journal。
4. 将旧凭证和 profile 移入同一 staging 账号目录，校验 staging 数据和目标注册条目。
5. 先将 staging 目录原子发布为正式账号目录，再原子提交名称为“默认账号”的 `accounts.json` 注册条目；两个动作之间由 journal 明确标识。
6. 注册表和正式账号目录都持久化成功后，清理 journal 和空旧目录；账号保持原登录状态，并计入 10 个上限。
7. 任何步骤失败或进程中断时，下一次启动必须先于普通注册表加载、账号恢复和注册表损坏处理执行 journal reconciliation。
8. reconciliation 必须根据源、staging、目标、注册表条目和 journal 阶段的组合，恢复到完整旧布局，或继续完成为一个已注册账号；不得存在无注册目录、重复默认账号或半迁移凭证。
9. 只有账号目录和注册表两个稳定终态都刷新到磁盘后才能删除 journal。无法自动恢复时保留旧文件、staging 和 journal，不进行破坏性清理，并显示具体错误码。

迁移实现必须可重复执行，并对文件移动、目录发布、注册表提交和 journal 清理的每个中断边界提供恢复规则。具体实现可以采用等价的崩溃安全事务协议，但必须满足“完整旧布局”或“一个完整已注册账号”两个稳定终态。

### 7.5 注册表损坏恢复

- 不自动删除任何账号目录、凭证或 profile。
- 将损坏的 `accounts.json` 按安全名称隔离，不记录其正文。
- 扫描合法 UUID 账号目录，重建默认禁用的恢复条目。
- 恢复条目使用临时本地名称，要求用户确认名称、顺序并主动重新启用。
- 不能从目录推断远端真实身份、原启用状态或原顺序。
- 恢复失败必须保留原数据并返回具体错误码。

## 8. Round Robin 调度

### 8.1 轮询单位

以下操作选择账号并推进轮询游标：

- 缓存未命中后真实发送的 Qwen 正式翻译尝试。
- 显式 Refresh 或 Bypass 产生的 Qwen 正式翻译尝试。
- 现有一次性输出 429/5xx 规则触发的第二次正式尝试。
- 设置页全局“测试连接”。

以下操作不选择账号或不推进游标：

- L1/L2 缓存命中。
- 固定账号的自动复检。
- 逐账号“测试”。
- 待验证账号被选中后、正式尝试前执行的账号复检。
- 登录、退出、删除、重命名和排序。

### 8.2 选择算法

算法固定为：

```text
从内存游标位置开始
  → 按显示顺序循环扫描账号
  → 跳过停用、未登录、登录中、登录过期、冷却中和忙碌账号
  → 遇到待验证账号时先固定账号复检
      → 成功：选择该账号执行正式尝试
      → 失败：进入冷却并继续扫描
  → 选择健康账号
  → 将游标移动到被选账号的下一位置
```

- 跳过账号不改变显示顺序。
- 账号复检本身不推进游标。
- 复检成功后紧接的正式尝试使用该账号。
- 应用重启后游标从头开始，不持久化公平性状态。
- 第一版不提供算法选择器、权重或随机因子。

### 8.3 没有直接可用账号

调度按以下顺序处理：

1. 检查是否存在已结束冷却的待验证账号，并按显示顺序复检。
2. 如果账号只是全部忙碌，等待最早一个账号释放；释放后重新按当前游标扫描，不绑定等待某个账号。
3. 等待始终受当前操作超时和 latest-wins 取消控制。
4. 如果仍无账号可用，立即返回可执行的账号池错误，不等待未来冷却结束。
5. 不自动回退 Official API。

错误必须区分账号池为空、全部停用、全部未登录、全部登录过期、冷却或待验证失败、全部忙碌超时以及混合不可用。

### 8.4 单账号并发限制

- 一个账号同一时间最多承担一次正式翻译尝试、正式重试、账号复检、全局测试或逐账号测试。
- 忙碌不是不健康，不改变健康判定。
- 不同账号可以并行工作。
- latest-wins 仍决定哪个用户翻译请求可以更新可见状态；它不等于全局账号池串行锁。
- 调度选择与账号 lease 获取必须是一个原子操作，防止两个并发操作同时选中刚刚空闲的同一账号。轮询游标在 lease 内保留候选位置，只有首个真实网络请求即将发送时才提交到被选账号的下一位置；发送前取消、请求构造失败或凭证借用失败不推进游标。

## 9. 正式重试与账号复检

### 9.1 保留的正式重试范围

首版严格保留当前正式重试范围，只改变第二次尝试的账号选择：

- 只有一次性输出模式会正式重试。
- 只有第一次正式尝试收到 429 或 5xx 时重试。
- 整个用户翻译请求最多两次正式尝试。
- 第二次正式尝试通过 Round Robin 重新选择账号。
- 如果没有其他健康账号，允许再次选择原账号。
- 网络错误、超时、401/403、协议错误和流式输出中断不新增正式重试。
- 流式输出已经收到的未完成译文继续遵守现有保留与不可复制规则。

这不是任意跨账号 failover；它只是把既有 429/5xx 第二次尝试纳入账号轮询。

### 9.2 自动复检触发

正式 Qwen 请求已经发出并最终发生以下错误时，固定原账号执行一次轻量复检：

- 网络错误。
- 请求超时。
- 429。
- 5xx。
- SSE 中断或未完成响应。
- 协议解码或响应结构错误。
- 其他能够反映 Qwen 连接或账号可用性的请求错误。

以下情况不执行自动复检：

- 401/403：直接标记登录过期。
- 配置校验失败。
- 原文为空或超过长度限制。
- 缓存错误。
- 用户取消或 latest-wins 取消。
- 请求尚未发送到 Qwen 的本地错误。
- 一次性输出的原请求总超时已经没有剩余时间。

### 9.3 自动复检行为

- 固定使用刚才出错的账号，不经过 Round Robin。
- 使用现有测试连接相同的真实轻量文本 `"hi"` 和当前目标语言。
- 沿用当前一次性输出或流式输出模式。
- 使用完全丢弃的进度和正文接收器，不向用户翻译请求发送 `PhaseChanged` 或 `ContentDelta`，测试译文不得进入未完成译文。
- 强制关闭 Qwen 网页历史。
- 强制绕过 L1/L2 缓存和 easyT 翻译历史。
- 最多执行一次，不因复检失败递归复检。
- 成功则账号保持或恢复健康；复检输出不能替代原正式尝试的结果。
- 失败则账号最后健康判定为不健康，进入五分钟冷却。
- 401/403 复检结果直接转登录过期。
- 每个发生错误的正式尝试所用账号分别接受复检。
- 一次性正式尝试失败后先同步复检并更新健康状态，再判断是否满足 429/5xx 正式重试条件。
- 流式正式尝试失败后立即向用户返回原错误；原账号继续保持占用，并在后台执行一次复检，完成后更新健康状态并释放占用。
- 复检成功不绑定后续正式重试账号；重试仍从当前轮询游标选择。

### 9.4 一次性输出总超时

- 一次性输出的账号等待、正式尝试、现有 backoff、自动复检和正式重试共同受用户翻译请求的原总超时约束。
- 一次性输出的自动复检不获得独立额外超时，不得使一次用户翻译超过设置的总超时。
- 总超时耗尽时不再发送复检或正式重试。
- 未能复检的出错账号记录为不健康，并在当前进程进入待验证；该最后健康判定持久化。
- 应用重启后该账号仍为待验证，但不恢复冷却剩余时间。
- 429/5xx 后的同步复检可能消耗全部剩余时间，使现有第二次正式尝试无法发出；这是账号健康优先和严格总超时共同产生的批准行为。

### 9.5 流式输出超时与后台复检

- 流式输出继续遵守既有正文静默超时：连接、首段正文和相邻正文等待使用 `timeoutSeconds`，有效正文到达后重置静默 deadline，不新增整次流式请求总时限。
- 流式请求最终失败后先结束用户翻译请求并返回原错误，不等待账号复检。
- 后台账号复检独立使用 `timeoutSeconds` 作为最长时间，不延长或改变已经结束的用户翻译请求。
- 后台复检期间账号保持使用中，不能承担其他正式尝试或测试。
- 后台复检成功、失败和 401/403 分别按既有健康规则更新账号，然后释放 lease。
- 应用退出取消后台复检并恢复复检前健康状态，不因此转为不健康或待验证。
- 流式失败不发起正式翻译重试。

### 9.6 冷却与恢复

- 复检失败后固定冷却五分钟。
- 冷却中账号不参与正式轮询。
- 冷却结束时不主动发请求，只转为待验证。
- 待验证账号被轮询扫描到时先复检；成功后执行当前正式尝试，失败后重新冷却五分钟。
- 用户可通过逐账号“测试”立即复检，不必等待冷却结束。
- 401/403 形成的登录过期不能通过冷却或复检自动恢复，必须重新登录。
- 停用账号必须由用户重新启用。

## 10. 手动测试

### 10.1 全局“测试连接”

- 保留设置页现有入口。
- 它验证账号池整体是否能够完成真实轻量翻译。
- 只在健康、已登录且已启用的账号中选择下一个账号，并原子取得 lease；只有真实测试即将发送时才推进轮询游标。
- 跳过忙碌账号；全部忙碌时等待最早释放，受测试超时控制。
- 不自动选择冷却中或待验证账号；用户通过逐账号“测试”提前验证这些账号。
- 成功时被测账号保持健康。
- 401/403 时被测账号转为登录过期。
- 其他失败时被测账号转为不健康并进入五分钟冷却。
- 无论成功或失败，只要真实测试已经发送，本次全局测试只推进一次游标；发送前取消、本地构造失败或凭证借用失败不推进。

### 10.2 逐账号“测试”

- 固定使用指定账号，不推进轮询游标。
- 账号忙碌时立即返回具体错误，不排队。
- 可用于提前验证冷却中或待验证账号。
- 成功转为健康。
- 401/403 转为登录过期。
- 其他失败转为不健康并进入五分钟冷却。

### 10.3 测试共同规则

- 使用现有真实轻量翻译逻辑，不仅检查本地 ticket 是否存在。
- 使用当前目标语言和当前一次性/流式输出设置。
- 强制关闭 Qwen 网页历史。
- 不读写 L1/L2 缓存。
- 不创建 easyT 翻译记录。
- 不显示为主页面用户翻译请求。
- 测试成功不显示错误码；测试失败显示具体错误码。

## 11. 翻译、缓存、历史与进度合同

### 11.1 TranslationBackend 边界

- `TranslationBackend` 继续作为 Official API 与 WebGateway 的唯一统一入口。
- Official API 不知道 Qwen 账号池存在。
- 账号选择、账号占用、复检、冷却和登录状态只属于 WebGateway/Qwen 内部。
- Tauri 翻译 command、前端翻译页面和翻译 store 不选择账号。

### 11.2 缓存

- 账号 ID、名称、顺序、健康状态和轮询游标不得进入缓存键。
- 所有 Qwen 账号继续共享现有 L1/L2 缓存。
- 缓存命中不选择账号、不占用账号、不推进游标。
- Refresh 和 Bypass 的真实正式尝试参与轮询。
- 测试与复检始终 Bypass，且不读不写缓存、不改变公开命中率。

### 11.3 easyT 翻译历史

- 一次用户翻译即使跨账号正式重试，完整成功后也只创建一条 easyT 翻译记录。
- 账号 ID、名称和健康状态不写入翻译历史。
- 测试与复检不创建翻译记录。
- 删除账号不修改历史记录。

### 11.4 Qwen 网页历史

- 每一次正式翻译尝试都必须继续遵守用户当前“保存到 Qwen 对话记录”设置，包括失败的第一次尝试和跨账号第二次尝试。
- 用户已确认：开启该设置时，第一次正式尝试和跨账号第二次正式尝试都会以保存远端历史的参数发送，实际能否形成远端会话由 Qwen 响应决定。
- 因此一次用户翻译可能在多个 Qwen 账号产生重复或失败的远端记录；设置页必须明确此行为。
- 测试和复检始终强制不保存远端历史。
- easyT 删除账号不能承诺删除 Qwen 远端历史。

### 11.5 latest-wins 与取消

- latest-wins 语义不变，只有最新请求更新可见翻译状态。
- 被新请求取代或用户取消不处罚账号，不触发复检。
- 取消应尽快释放账号占用。
- 应用退出取消登录 watcher、关闭登录窗口并取消复检，不等待网络完成。退出中断的复检恢复复检前健康状态，不将账号判为不健康或待验证；已经在复检前完成的健康状态更新不回滚。

### 11.6 翻译阶段进度

- 不增加“账号选择”“账号复检”或“账号冷却”用户可见翻译阶段。
- 继续遵守 `docs/翻译请求阶段进度需求与架构共识文档.md` 的五阶段模型。
- Qwen 网络连接仍使用 `connectingBackend`。
- 自动复检使用丢弃 reporter，不发送任何主翻译页进度事件。
- 只有正式跨账号重试使用新的 `connectingBackend` sequence，使阶段计时归零，总耗时持续累计。
- 进度事件不包含账号 ID、账号名称、账号数量或轮询位置。
- 设置页测试连接仍不属于主翻译页阶段进度范围。

- 错误反馈固定在安全中文消息末尾显示 `[错误码]`。

## 13. 目标架构与所有权

### 13.1 模块结构

```text
TranslationBackend
└── WebGateway
    └── QwenAccountPool
        ├── AccountRegistry
        ├── QwenAccount[]
        │   ├── QwenSession
        │   ├── CredentialStore
        │   ├── BrowserProfile
        │   └── HealthState
        ├── RoundRobinScheduler
        ├── AccountLease
        └── QwenRequestExecutor
```

职责：

- `QwenAccountPool`：账号集合、状态查询和账号级操作的统一入口。
- `AccountRegistry`：注册表校验、原子持久化、迁移和损坏恢复。
- `QwenSession`：单账号登录状态、凭证借用和登录 watcher 控制。
- `RoundRobinScheduler`：可选账号过滤、游标和忙碌等待。
- `AccountLease`：保证单账号同一时间最多一项 Qwen 网络操作，并在取消、失败或 panic-safe 清理路径释放。
- `QwenRequestExecutor`：复用当前 Qwen 私有 DTO、Header、SSE 解码和安全错误映射。

不得为未来 WebGateway 供应商预先建设动态插件系统；第一版继续显式支持 Qwen。

### 13.2 状态所有权

- Rust 是账号列表、登录、健康、冷却、占用和轮询游标的唯一权威。
- 前端 controller 只调用统一 Tauri service 并展示快照，不自行推导健康状态或 Round Robin。
- 账号注册表不进入 `AppConfig`；Qwen 模型和保存网页历史仍属于现有 `WebGatewayConfig`。
- 页面和展示 module 不直接调用原始 `invoke`。

### 13.3 登录窗口安全

- 登录窗口继续使用固定 Qwen URL 和允许 host 列表。
- 登录窗口 label 必须能映射当前唯一登录流程和目标 `accountId`，但远端页面不获得新增 Tauri command 权限。
- Cookie watcher 只读取目标 cookie，内存 ticket 在使用后继续 zeroize。
- 不在导航日志中记录 query、fragment、ticket 或 OAuth 参数。

## 14. 错误合同

### 14.1 结构化错误

所有 Qwen 账号池、登录、测试、复检和正式翻译错误必须通过 IPC 提供：

```text
QwenCommandError
├── code：稳定错误码
├── kind：程序错误类别
├── message：安全中文消息，不含错误码
└── totalElapsedMs?：适用时提供
```

前端固定展示：

```text
{message} [{code}]
```

规则：

- 前端不得从中文消息解析错误码。
- 错误码使用大写 ASCII，格式为 `QW-<DOMAIN>-<NUMBER_OR_HTTP>`。
- 已发布错误码不得改变含义、删除后复用或重新分配。
- 用户文案可以优化，但错误码保持稳定。
- 新错误只能新增编码。
- 成功状态不显示错误码。
- 复制用户可见错误文本时包含错误码。

### 14.2 首版错误码目录

#### 账号池 `POOL`

| 错误码 | 含义 | 用户处置 |
|---|---|---|
| `QW-POOL-001` | 账号池为空 | 添加账号 |
| `QW-POOL-002` | 已达到 10 个账号上限 | 删除不需要的账号 |
| `QW-POOL-003` | 全部账号已停用 | 启用至少一个账号 |
| `QW-POOL-004` | 全部账号未登录 | 登录至少一个账号 |
| `QW-POOL-005` | 全部账号登录过期 | 重新登录至少一个账号 |
| `QW-POOL-006` | 全部候选账号冷却中或待验证失败 | 稍后重试或逐账号测试 |
| `QW-POOL-007` | 全部账号忙碌且等待超时 | 稍后重试 |
| `QW-POOL-008` | 指定账号不存在 | 刷新账号列表 |
| `QW-POOL-009` | 指定账号正在使用中 | 等待当前操作完成 |
| `QW-POOL-010` | 混合状态下没有可用账号 | 按账号状态逐项处理 |
| `QW-POOL-011` | 账号名称无效 | 修改为 1 至 40 字符的合法名称 |
| `QW-POOL-012` | 账号顺序操作无效 | 刷新后重试 |

#### 登录 `LOGIN` 与认证 `AUTH`

| 错误码 | 含义 | 用户处置 |
|---|---|---|
| `QW-LOGIN-001` | 另一个账号正在登录 | 完成或取消现有登录 |
| `QW-LOGIN-002` | 登录窗口创建、显示或聚焦失败 | 重试登录 |
| `QW-LOGIN-003` | Cookie 读取失败 | 关闭窗口后重试 |
| `QW-LOGIN-004` | 登录 watcher 超时 | 重新登录 |
| `QW-LOGIN-005` | 登录凭证保存失败 | 检查本地存储后重试 |
| `QW-AUTH-401` | Qwen 返回 HTTP 401 | 重新登录该账号 |
| `QW-AUTH-403` | Qwen 返回 HTTP 403 | 重新登录该账号 |

用户主动取消登录是正常状态转换，不作为错误；若取消动作本身失败，则使用对应窗口或内部错误码。

#### 存储 `STORAGE`

| 错误码 | 含义 | 用户处置 |
|---|---|---|
| `QW-STORAGE-001` | 账号凭证损坏 | 退出后重新登录 |
| `QW-STORAGE-002` | 账号注册表损坏但已进入恢复流程 | 检查恢复账号并重新启用 |
| `QW-STORAGE-003` | 账号注册表恢复失败 | 保留数据并报告错误码 |
| `QW-STORAGE-004` | 账号数据读取失败 | 检查文件权限或磁盘 |
| `QW-STORAGE-005` | 注册表或凭证写入失败 | 检查文件权限或磁盘 |
| `QW-STORAGE-006` | 账号 profile 初始化失败 | 检查文件权限或磁盘 |
| `QW-STORAGE-007` | 账号 profile 或目录删除失败 | 关闭相关窗口后重试 |
| `QW-STORAGE-008` | 旧单账号数据迁移失败 | 保留旧数据并重启重试 |

#### 网络与上游 `NET` / `UPSTREAM`

| 错误码 | 含义 | 用户处置 |
|---|---|---|
| `QW-NET-001` | DNS、连接、TLS 或其他安全归一化网络错误 | 检查网络后重试 |
| `QW-NET-408` | 已进入具体 Qwen 网络请求后的请求超时 | 检查超时设置后重试 |
| `QW-UPSTREAM-429` | Qwen 返回 HTTP 429 | 等待冷却后重试 |
| `QW-UPSTREAM-5XX` | Qwen 返回 HTTP 500 至 599 | 稍后重试 |
| `QW-UPSTREAM-001` | Qwen 私有协议结构不匹配 | 更新 easyT 或报告错误码 |
| `QW-UPSTREAM-002` | Qwen 响应格式无效 | 稍后重试或报告错误码 |
| `QW-UPSTREAM-003` | 流式响应不完整 | 查看未完成译文并重试 |
| `QW-UPSTREAM-004` | 当前 Qwen 响应不支持所需流式行为 | 关闭流式输出或报告错误码 |
| `QW-UPSTREAM-005` | 其他非 2xx Qwen 状态 | 按安全消息处理 |

#### 内部错误

| 错误码 | 含义 | 用户处置 |
|---|---|---|
| `QW-INTERNAL-001` | 无法归入以上稳定类别的内部错误 | 报告错误码和复现步骤 |

### 14.3 HTTP 状态展示

- 401 和 403 分别使用 `QW-AUTH-401`、`QW-AUTH-403`。
- 429 使用 `QW-UPSTREAM-429`。
- 500 至 599 共用 `QW-UPSTREAM-5XX`；安全消息可以显示实际状态，例如“Qwen 服务暂时不可用（HTTP 503）”。
- 其他非 2xx 使用 `QW-UPSTREAM-005`，安全消息可显示状态码。
- 任何情况都不得展示 URL、Header、Cookie、ticket 或 response body。

### 14.4 日志

日志允许记录：

- 错误码。
- 稳定错误类别。
- HTTP 状态码。
- 账号本地 UUID 的脱敏短标识。
- 操作类别和允许的计数。

日志禁止记录：

- 账号名称。
- 完整 UUID。
- ticket、Cookie、Header 或凭证派生值。
- 原文、译文、轻量测试响应正文或上游 response body。
- 登录 URL query、fragment 或 OAuth 参数。

## 15. 安全与隐私

- 每个账号凭证继续以用户已批准的明文文件保存，设置页必须明确本地风险。
- 每个账号 profile 隔离，禁止多个账号共享 Cookie 目录。
- 凭证只在 Rust 内存和账号目录中存在，不经 IPC 传给前端。
- 账号注册表、缓存、历史和配置不得包含凭证。
- 远程 Qwen WebView 不得获得账号管理、文件、缓存或翻译 command capability。
- 删除账号是本地删除，不代表远端注销或远端数据删除。
- 测试与复检不携带用户原文，使用固定轻量文本。
- 自动复检不能递归，避免故障时形成请求风暴。
- 不为全部账号创建永久健康检查 timer。

## 16. 关键场景

### 16.1 缓存命中

```text
用户翻译
→ L1/L2 命中
→ 返回译文
→ 不选择账号，不推进游标
```

### 16.2 两个健康账号

```text
请求 A：账号 1
请求 B：账号 2
请求 C：账号 1
```

显示顺序决定轮询顺序，应用重启后从第一个可用账号重新开始。

### 16.3 429 后跨账号重试

```text
正式尝试 1：账号 1 返回 429
→ 固定账号 1 轻量复检
→ 按现有规则允许第二次正式尝试
→ Round Robin 选择账号 2
→ 成功后只写一条 easyT 翻译历史
```

开启 Qwen 网页历史时，两次正式尝试都必须使用保存远端历史的参数，并可能留下远端会话。

### 16.4 一次性输出网络失败但复检成功

```text
账号 1 正式尝试网络失败
→ 账号 1 轻量复检成功
→ 账号 1 保持健康
→ 原翻译仍返回网络错误
→ 不新增正式重试
```

### 16.5 复检失败

```text
账号 1 正式尝试失败
→ 账号 1 复检失败
→ 账号 1 冷却五分钟
→ 429/5xx 场景可以轮询账号 2 正式重试
```

### 16.6 一次性输出总超时耗尽

```text
正式尝试耗尽总超时
→ 不再发送复检或重试
→ 原账号进入待验证
→ 后续轮询命中时先复检
```

### 16.7 全部账号忙碌

```text
新正式尝试
→ 等待最早账号释放
→ 在剩余总超时内重新 Round Robin
→ 超时则 QW-POOL-007 或 QW-NET-408
```

池选择阶段使用 `QW-POOL-007`；已经进入具体 Qwen 请求后超时使用 `QW-NET-408`。

流式输出等待账号使用 `timeoutSeconds` 作为本次调度等待上限，但正文开始后继续使用既有静默 deadline，不建立整次请求总时限。

### 16.8 流式输出失败

```text
账号 1 流式正式尝试失败
→ 立即向用户返回原错误并保留现有未完成译文语义
→ 账号 1 保持使用中
→ 后台使用丢弃 sink 复检，最长 timeoutSeconds
→ 更新账号健康状态并释放 lease
```

复检的 `"hi"` 译文和阶段事件不得进入用户翻译状态。

### 16.9 401/403

```text
账号 1 返回 401/403
→ 不发送复检
→ 账号 1 标记登录过期并持久化
→ 原请求返回具体 AUTH 错误码
→ 用户重新登录后恢复
```

## 17. 验证要求

### 17.1 Rust 自动测试

必须覆盖：

- 注册表 round-trip、原子替换、schema 校验和损坏恢复。
- 旧单账号迁移成功、中断、重复启动和失败不丢数据。
- 最多 10 个账号、名称校验、允许重名和顺序调整。
- Round Robin 基本公平性、跳过不可用账号和重启游标。
- 缓存命中不推进游标。
- 待验证账号复检成功/失败路径。
- 单账号 lease、防并发和取消释放。
- 全部忙碌等待、超时和 latest-wins 取消。
- 一次性输出 429/5xx 最多一次跨账号正式重试。
- 一次性输出网络、超时和协议错误只同步复检、不新增正式重试。
- 流式错误先返回原错误，再使用独立静默预算后台复检，不新增正式重试。
- 401/403 不复检并持久化过期。
- 一次性输出总超时无剩余时不复检，账号转待验证。
- 复检不递归、不推进游标、不读写缓存或历史，并丢弃全部正文和进度事件。
- 测试和复检强制关闭 Qwen 网页历史。
- 删除、退出、重新登录原子性和忙碌保护。
- 应用退出取消 watcher/复检不处罚账号。
- 每个错误分支返回稳定 `code` 和脱敏 `message`。
- 日志和 IPC 不包含凭证、账号名称、原文或上游 body。

### 17.2 前端自动测试

必须覆盖：

- 账号列表八种状态及状态优先级。
- 添加、重命名、启用/停用、上移/下移。
- 10 个账号时禁用添加。
- 全局测试与逐账号测试的 loading、成功和错误码。
- 忙碌账号操作禁用矩阵。
- 单一登录流程占用提示。
- 退出和删除 `ConfirmDialog`。
- 名称 `FormField` 校验与焦点恢复。
- 冷却剩余时间只在设置界面可见期间更新。
- 默认和最小窗口下滚动、换行、键盘操作与可访问名称。
- 前端使用结构化 `code`，不解析中文消息。

### 17.3 集成与人工验收

真实账号测试需要项目所有者明确允许使用凭证和产生 Qwen 请求。必须覆盖：

1. 两个不同账号独立登录，确认 profile 和 Cookie 不串号。
2. 连续真实请求按显示顺序轮询。
3. 缓存命中不消耗轮询位置。
4. 全局测试推进游标，逐账号测试不推进。
5. 一个账号退出、过期、停用和冷却时正确跳过。
6. 重新登录取消后旧凭证仍可用。
7. 退出后 profile 已删除，再登录不恢复旧 Cookie。
8. 开启 Qwen 网页历史时，跨账号重试可能产生多个远端会话。
9. 设置页在 `520x390` 和 `360x200` 下无重叠、溢出或不可达操作。
10. 错误消息显示具体错误码且不泄漏敏感信息。

无法安全制造真实 429、401、403、5xx 或协议损坏时，使用可控测试服务和 fixture 验证自动行为；不得滥用真实账号触发风控。

## 18. Definition of Done

- [ ] 单账号无并发 Qwen 操作，全部忙碌时按规则等待。
