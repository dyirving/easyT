# 02 — 实现无选区显示恢复与有效选区翻译

**What to build:** 在非设置页使用当前全局翻译快捷键时，先在后台串行执行选区捕获，并根据结果完成一条端到端路径：有效原文继续快捷翻译；无选区执行显示恢复并完整保留当前翻译状态；其他捕获故障取代旧结果并展示可操作的错误。捕获结果确定前，用户当前看到的状态不得被清空或闪烁替换。

**Blocked by:** None — can start immediately and may proceed in parallel with 01 — 按键周期内只激活一次快捷键. Implementation still requires the source SDD to be explicitly approved.

**Status:** ready-for-agent

**Source:** `docs/SDD-shortcut-no-selection-window-restore.md`，重点覆盖 FR-001 至 FR-004、FR-007 至 FR-009、NFR-001、NFR-002、NFR-004、NFR-005、T-005 至 T-010。

- [ ] 选区捕获返回前不切换路由、不显示或移动窗口，也不清空、替换或取消当前翻译状态。
- [ ] 捕获到有效原文后立即创建新的翻译请求、清除旧译文，并沿用现有定位、显示、聚焦和翻译行为。
- [ ] 快捷键捕获返回 `NoSelectedText` 时不创建请求、不写入错误、不移动窗口，只切到翻译界面并显示、聚焦窗口。
- [ ] 无选区显示恢复逐字段保留空闲、成功、流式生成、未完成译文和错误状态，并允许已有请求继续更新。
- [ ] 非 `NoSelectedText` 捕获故障清除旧原文和译文、使旧请求的迟到更新失效，并显示现有错误界面。
- [ ] 无原文的捕获故障不显示无效重试按钮；已有原文的可重试翻译故障仍可重新翻译。
- [ ] 底层选区捕获严格串行，任何时刻最多执行一个捕获；前一次失败不会阻断后续捕获。
- [ ] 连续两次有效选区由较新的翻译请求拥有最终可见状态；后续无选区不会使先前捕获或翻译失效。
- [ ] 全空白文本仍判定为无选区；有效文本继续去除首尾空白并保留内部格式。
- [ ] 删除新流程不再可达的可见捕获状态和相关死接口，但保留手动翻译及其他既有翻译状态行为。
- [ ] Store、协调器和页面自动化测试覆盖正常、无选区、捕获故障、并发和迟到更新场景。
- [ ] 前端测试和类型检查通过，并记录命令证据。
