> 本文是 easyT 术语表功能的产品与架构共识来源。实施前应基于本文形成 SDD；若实现与本文冲突，必须停止受影响部分并请求项目所有者决定。

## 1. 背景与目标

easyT 是以英文原文为输入的翻译软件。用户需要为专业术语、项目名称和多义词指定稳定译法，例如在技术语境中将 `function` 优先译为“函数”。

术语表第一版必须：

- 让用户在本地管理英文源术语到指定译法的条目。
- 对 Official API 与 Qwen 网页实验模式使用语义相同的术语约束。
- 使当前术语表优先于冲突的旧缓存结果。
- 保持 L1/L2 精确缓存，尽量复用仍符合当前术语规则的结果。
- 保持翻译历史、latest-wins、流式输出和现有顶部“重新翻译”行为。
- 使用现有 UI Kit，不新增 UI dependency。

## 2. canonical 术语

本文沿用根 `CONTEXT.md` 中的术语，尤其是“术语表”“术语条目”“源术语”“指定译法”和“有效术语集”。

补充约束：

- 术语表是用户维护的翻译约束集合，不是翻译缓存，也不是翻译记忆。
- 源术语是当前英文原文中待识别的词或短语。
- 指定译法是匹配后交给模型优先采用的目标语言表达，不是对模型输出的事后字符串替换。
- 有效术语集只包含本次请求中实际匹配、目标语言一致、术语表总开关开启且条目启用的条目。

## 3. 范围

### 3.1 第一版包含

- 最多 200 条本地术语条目。
- 每条绑定一个现有的目标语言。
- 添加、编辑、删除、单条启用/停用和术语表总开关。
- 搜索、分页、Dialog 内管理和删除二次确认。
- 请求开始时生成不可变的有效术语集。
- 共享 Prompt 注入、缓存身份区分、文件损坏隔离和恢复提示。

### 3.2 第一版不包含

- 译文后字符串替换、强制替换或模型遵守检测。
- 非英文源术语。
- 正则表达式、模糊匹配、词形还原、手工优先级或术语分组。
- CSV、TBX 或其他格式导入导出。
- 云同步、共享协作、术语统计、自动抽取或历史术语版本追溯。
- 依翻译后端、模型或 Qwen 账号分别配置术语。

## 4. 条目与状态

### 4.1 条目模型

```text
TermEntry
├── id                 稳定 UUID
├── sourceTerm         英文源术语
├── targetLanguage     现有目标语言列表中的一项
├── targetTerm         指定译法
├── enabled            单条启用状态
├── caseSensitive      是否大小写敏感，默认 false
├── createdAt
└── updatedAt
```

约束：

- `sourceTerm` 必须为 1 至 120 个 Unicode 字符。
- `targetTerm` 必须为 1 至 240 个 Unicode 字符。
- 两个字段都不得只包含空白，也不得包含控制字符。
- 目标语言只能从 easyT 当前支持的目标语言列表中选择。
- 条目操作必须立即原子保存；编辑 Dialog 的草稿在点击“保存”前不得影响翻译，取消不改变原条目。

### 4.2 启用规则

- 术语表总开关默认关闭。
- 总开关与单条 `enabled` 都为开启时，该条目才可能进入有效术语集。
- 关闭总开关不修改任何单条启用状态。
- 总开关开启但没有启用条目时，等同没有术语约束。
- 总开关切换和单条启停都立即持久化，并只影响之后开始的翻译请求。

## 5. 匹配与冲突规则

### 5.1 基础匹配

- 只匹配英文原文。
- 英文、数字和下划线组成的源术语按完整单词匹配，`function` 不匹配 `functional`。
- 包含空格、连字符或标点的英文术语按精确子串匹配。
- 匹配作用于完整原文，不因 Markdown 代码块、行内代码或 LaTeX 公式而跳过。
- 条目只在目标语言与当前翻译请求的目标语言一致时参与。

### 5.2 大小写敏感例外优先

大小写敏感条目与不敏感条目可以共存。匹配顺序固定为：

1. 大小写敏感且源术语完全相同的条目。
2. 大小写不敏感的默认条目。

例如允许：

```text
china -> 瓷器，大小写不敏感
China -> 中国，大小写敏感
```

原文 `China` 只使用“中国”；原文 `china` 与 `CHINA` 使用“瓷器”。

重复限制：

- 同一目标语言下，大小写敏感条目的源术语完全相同时，不能有两个不同条目。
- 同一目标语言下，大小写不敏感条目的源术语按忽略大小写规范化后必须唯一。
- Prompt 只注入最终胜出的条目，禁止同时注入相互矛盾的指定译法。

### 5.3 重叠与排序

- 多个源术语重叠时，更长的源术语优先，例如 `neural network` 优先于 `network`。
- 最终有效术语集按源术语长度降序，再按规范化源术语、大小写规则和指定译法稳定排序。
- 稳定排序同时用于 Prompt 渲染和缓存身份，避免等价术语集产生不同缓存键。

## 6. 翻译与 Prompt

### 6.1 生成方式

术语表只通过共享系统 Prompt 影响生成结果。Official API 与 Qwen 必须使用同一语义的术语约束，不能各自读取术语表或实现匹配。

术语条目以紧凑、结构化的文本注入，例如：

```text
以下是翻译约束；仅在原文术语匹配且语义适用时优先采用右侧译法：
function => 函数
neural network => 神经网络
```

模型仍负责理解语境。第一版不做返回后的检测、警告或字符串替换。

### 6.2 全量注入

- 单个术语表最多保存 200 条。
- 当前原文实际命中多少有效术语，就注入多少，最多 200 条。
- 不设置本地 Prompt 字节上限，不静默截断或省略命中条目。
- 请求仍正常发送；已知的上下文或 Prompt 过长错误要显示专项提示。
- 若上游只返回通用错误，保留真实错误分类，并建议用户暂时关闭术语表后重试，不得谎称已确认术语过长。
- 第一版不在翻译页面展示本次命中的术语数量或明细。

### 6.3 请求快照

翻译请求开始时固定 AppConfig 快照和 Termbase 快照，并从中生成有效术语集。设置页之后的任何术语修改不得改变正在进行的普通或流式翻译请求。

## 7. 缓存

### 7.1 缓存身份

术语表和缓存存储不同数据：术语表存规则，缓存存完整译文。缓存查询顺序继续为 L1 -> L2 -> 翻译后端。

每次翻译先解析有效术语集，再用下列材料生成 L1/L2 共用 CacheKey：

```text
domain
cache_key_version
prompt_version
normalized_source_text
trimmed_target_language
effective_termbase_fingerprint
```

`effective_termbase_fingerprint` 是最终注入 Prompt 的规范化有效术语集的确定性摘要。它不依赖条目 UUID、创建时间、更新时间、未启用条目或未命中条目。

### 7.2 不变量

- 当前术语表命中且与旧缓存译文冲突时，术语表优先；旧缓存不得命中。
- 例如缓存中 `function -> 功能` 来自无术语约束，而当前有效术语集为 `function -> 函数` 时，必须重新翻译并以新键写入 L1 与 L2。
- 有效术语集相同，两个缓存层都可以命中。
- 修改未命中当前原文的术语、条目时间或其他不影响有效术语集的元数据，不得降低该请求的缓存命中率。
- 总开关关闭、没有启用条目或没有任何匹配条目时，缓存身份均视为“无术语约束”，可以复用既有无术语缓存。
- 删除术语后可复用无术语缓存；恢复完全相同的术语规则后可复用对应的带术语缓存。
- 术语表加入 CacheKey 编码与输出影响参数集合时，必须提升 `CACHE_KEY_VERSION`；共享 Prompt 模板变化时必须提升 `PROMPT_VERSION`。
- 旧缓存不主动删除，继续按现有 L1/L2 LRU 规则淘汰。

Refresh、Qwen `saveHistory=true` 与连接测试继续遵循现有 Bypass 规则。连接测试不解析或注入术语表。

## 8. 本地存储与恢复

术语表独立于 `AppConfig` 和翻译历史：

```text
easyT_Data/
└── termbase/
    └── termbase.json
```

文件采用带 schema version 的 JSON 文档，并使用“写临时文件 -> flush -> 原子替换”提交。

根对象至少包含：

```text
TermbaseDocument
├── schemaVersion
├── enabled
└── entries
```

文件损坏、schema 不兼容或校验失败时：

1. 保留原文件并按时间戳隔离。
2. 创建空术语表，且总开关关闭。
3. 翻译继续进行，并视为无术语约束。
4. 设置页显示一次非阻断恢复提示。

日志不得记录术语内容、完整 Prompt、原文、译文、API Key、Cookie 或 Qwen ticket。

## 9. 模块与接口

新增 Rust `Termbase` 深模块。建议目录：

```text
src-tauri/src/termbase/
├── mod.rs
├── model.rs
├── storage.rs
└── matcher.rs
```

对外 interface：

```text
snapshot() -> TermbaseSnapshot
create(entry) -> TermbaseSnapshot
update(id, entry) -> TermbaseSnapshot
delete(id) -> TermbaseSnapshot
set_enabled(enabled) -> TermbaseSnapshot
set_entry_enabled(id, enabled) -> TermbaseSnapshot
resolve(source_text, target_language) -> EffectiveTermbase
```

Termbase 负责存储、校验、冲突解析、匹配、Prompt 数据和缓存指纹；不负责网络请求、缓存存储、翻译历史、latest-wins、UI 焦点或 Qwen 账号选择。

`TranslationBackend` 在缓存查询前调用 `resolve`，将同一份有效术语集同时交给缓存键与共享 Prompt 构造。适配器不得绕开这个 seam 自行读取术语表。

## 10. 设置页

设置页显示紧凑入口：

```text
术语表                                      12 条
[管理术语表]
```

“管理术语表”打开现有 `Dialog`。Dialog 提供：

- 总开关。
- 本地搜索，按源术语和指定译法进行不区分大小写的包含匹配。
- 每页 20 条，搜索条件变化后回到第 1 页。
- 添加、编辑、单条启停和删除。
- 删除使用 `ConfirmDialog` 二次确认。

术语操作使用独立 Tauri command 并立即保存，不依赖设置页底部“保存设置”。每次成功操作返回完整权威快照，前端不得自行推导匹配、冲突或排序结果。

默认窗口 `520x390` 和最小窗口 `360x200` 下，Dialog 列表区域必须独立滚动，分页和操作不得溢出，所有操作可用键盘完成。

Qwen 开启“保存到 Qwen 对话记录”时不增加术语表专有提示；沿用现有对翻译请求内容可能保存到网页端的说明。

## 11. 翻译历史与刷新

术语表不修改历史 schema，也不回写既有历史记录。翻译历史用于回看与复制，不提供“从历史记录重新翻译并替换旧记录”。

顶部当前译文的“重新翻译”和错误态重试继续存在：它们使用现有 Refresh 语义，绕过缓存读取并在成功后更新当前 CacheKey 对应的共享缓存。

## 12. 验收标准

- Official API 与 Qwen 接收语义相同的术语 Prompt。
- `china` 与 `China` 的大小写敏感例外按第 5.2 节工作，且冲突译法不同时注入。
- 命中术语全部注入，绝不因本地数量或字节限制静默遗漏。
- 有效术语变化时旧冲突缓存不命中；无效术语变化时正确缓存仍命中。
- 总开关关闭、空术语表和零命中时复用无术语缓存。
- 总开关和单条启停立即保存，只影响后续请求。
- 删除与恢复相同术语规则时按第 7.2 节复用正确缓存。
- 文件损坏隔离后翻译继续，设置页显示一次恢复提示。
- CRUD、匹配、大小写优先级、重叠排序、Prompt 渲染、缓存键、L1/L2、错误提示、存储恢复、搜索分页和无障碍交互均有自动测试。
- 完成 `npm run typecheck`、`npm test`、`npm run build`、`cargo test --manifest-path src-tauri/Cargo.toml`、`cargo build --release --manifest-path src-tauri/Cargo.toml`，并按 UI Kit 文档完成默认和最小窗口人工检查。
