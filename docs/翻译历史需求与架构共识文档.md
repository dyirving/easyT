## 1. 背景

easyT 当前以单次翻译请求为主要展示模型。连续阅读文献时，用户翻译第二段后仍需要查看第一段，但当前界面只保留一个主要翻译状态，无法形成连续阅读记录。

本需求增加持久化翻译历史，使用户能够：

- 始终在顶部查看当前活动请求或最新译文。
- 在下方按顺序回看之前的翻译记录。
- 折叠不需要立即阅读的记录，控制小窗口内容密度。
- 分别复制译文或一次复制原文和译文。
- 使用当前配置重新翻译任意历史记录。
- 在主界面快速清空全部翻译历史。
- 自定义持久化历史的最大保留条数。

## 2. 目标

必须达到：

- 翻译记录跨应用重启持久化。
- 最新译文位于所有翻译记录顶部，其他记录位于下方并默认折叠。
- 保持当前翻译请求的 latest-wins、缓存、流式输出和阶段进度语义。
- 历史存储与 L1/L2 翻译缓存严格分离。
- 按需加载历史正文，避免启动时加载和渲染全部 Markdown、LaTeX 与 KaTeX。
- 在设置页允许选择或输入历史记录上限，默认 5 条，最大 20 条。
- 复用并扩展 easyT 内部 UI Kit，不引入新 UI dependency。
- 历史模块故障不得把成功的翻译变成翻译失败。

## 3. 非目标

第一版不包含：

- 从旧版当前译文、L1、L2、日志或其他来源迁移历史数据。
- 单条历史删除、批量选择或历史管理模式。
- 历史搜索、筛选、收藏、标签、导出或云同步。
- 历史分页或虚拟列表；最大记录数已经限制为 20。
- 历史数据库加密。
- 历史数据库大小和路径的设置页详情。
- 数据库总字节容量限制。
- 存储介质级安全擦除。
- 从翻译缓存反向构造历史。
- 新的请求代次、并发控制或缓存策略。
- 多选、异步搜索、分组或虚拟滚动 Combobox。
- 折叠高度动画或复杂手风琴系统。

## 4. canonical 术语

本文沿用根 `CONTEXT.md` 中的翻译领域术语，并增加：

**翻译记录**  
一次完整成功且仍属于当前 active 请求的翻译行为所形成的持久化记录。缓存命中也属于新的翻译行为，因此会形成新的翻译记录。

**最新译文**  
持久化翻译记录中排序最新的一条完整记录。它位于所有其他翻译记录上方并默认展开。

**翻译历史**  
持久化保存的全部翻译记录集合，包括最新译文。设置中的 N 表示该集合的总记录数上限。

**历史摘要**  
用于折叠列表和启动恢复的轻量数据，包括稳定身份、原文摘要、译文摘要、完成时间和少量来源元数据，不包含完整正文。

**临时成功结果**  
翻译已经完整成功，但历史持久化失败或超限，因而只能在当前进程内展示的结果。它不计入持久化历史数量，应用退出后可能丢失。

**全部复制**  
按“完整原文、一个空行、完整译文”的顺序复制文本，不包含界面标签和元数据。

## 5. 核心产品模型

### 5.1 页面记录顺序

翻译记录始终使用倒序展示：

```text
当前活动请求，或最新译文（默认展开）

翻译历史 3 / 5                         [清空历史]
├── 次新记录（默认折叠）
├── 更早记录（默认折叠）
└── 最旧记录（默认折叠）
```

规则：

- 存在活动请求时，活动请求占据顶部。
- 不存在活动请求时，持久化记录中最新一条占据顶部并默认展开。
- 其余记录位于下方，按照完成时间倒序排列并默认折叠。
- 新翻译请求开始时，原最新译文进入下方历史显示区并折叠。
- 新请求失败时，失败状态继续显示在顶部；此前成功记录仍可在下方查看。
- 新请求开始时所有历史条目统一折叠。
- 多条历史可以由用户同时展开，不采用互斥手风琴。
- 展开状态只属于当前前端运行时，不写入数据库或配置。

### 5.2 应用启动恢复

历史完成顺序为 A → B → C 时，重新启动后恢复为：

```text
C：最新译文，默认展开
B：历史记录，默认折叠
A：历史记录，默认折叠
```

启动恢复必须满足：

- 恢复全部保留范围内的摘要，保持确定性倒序。
- 最新一条恢复完整正文并作为顶部最新译文。
- 恢复行为不创建新的翻译记录、不更新时间，也不调用翻译后端。
- 历史为空时进入现有 idle 状态。
- 启动时先显示轻量状态“正在加载翻译历史…”，不能先显示 idle 再跳出历史。
- 历史初始化完成前，暂不允许手动输入翻译或选区翻译，避免初始化与写入竞态。
- 窗口创建、打开设置和关闭窗口不被历史加载阻塞。

### 5.3 进入历史的结果

只有完整成功且仍属于当前 active 请求的结果才能持久化。

| 场景 | 是否保存 |
|---|---:|
| 普通网络翻译完整成功 | 是 |
| L1/L2 缓存命中 | 是 |
| 手动输入翻译成功 | 是 |
| 流式输出收到完整结束信号 | 是 |
| 历史重新翻译完整成功 | 是，替换原记录 |
| 翻译失败 | 否 |
| 超时、取消 | 否 |
| 未完成译文 | 否 |
| 被更新请求覆盖 | 否 |
| 迟到返回的旧请求 | 否 |
| 无选区，仅显示恢复 | 否 |
| 测试连接 | 否 |
| 登录或配置操作 | 否 |

重复翻译完全相同的原文不去重。翻译历史记录用户行为，缓存负责复用结果，两者语义不同。

## 6. 主界面交互

### 6.1 手动输入入口

手动输入必须在恢复历史后仍可使用，不能要求用户先清空历史。

```text
手动输入文本（可折叠）

当前活动请求或最新译文

翻译历史 N / 上限                       [清空历史]
其他记录
```

规则：

- 没有翻译记录时，手动输入区域默认展开。
- 已有最新译文或历史时，手动输入区域默认折叠。
- 折叠时保留尚未提交的输入文本。
- 开始手动翻译后折叠输入区，并只执行一次滚动到顶部。
- 手动翻译失败后保留输入内容，方便修改或重试。
- 应用重启不恢复未提交的手动输入。
- 活动请求期间手动输入控件禁用。

### 6.2 原文、译文与记录折叠

- 顶部最新译文的原文和译文可以分别独立折叠。
- 顶部最新译文默认原文、译文都展开。
- 下方历史先整体折叠，只展示摘要与完成时间。
- 展开历史记录后，原文和译文默认都展开，并且仍可分别折叠。
- 活动请求期间原文可以折叠；正在生成的译文和阶段进度不可折叠。
- 折叠译文时卸载 Markdown/KaTeX 渲染树。
- 折叠不删除已经加载的字符串；是否保留完整正文由历史前端状态统一管理。
- 新请求开始后所有下方历史恢复为折叠状态。

### 6.3 折叠摘要

折叠记录固定显示：

```text
原文：Self-supervised learning enables...
译文：自监督学习使……
今天 14:32
```

规则：

- 原文摘要一行，译文摘要一行，超出部分省略。
- 展示摘要时把换行显示为空格，但不修改数据库中的正文。
- 原文摘要和译文摘要分别最多保存 160 个 Unicode 字符。
- 折叠摘要不解析或渲染 Markdown、LaTeX、KaTeX。
- 折叠状态不显示模型、供应商、耗时或缓存来源。
- 展开后显示目标语言、完成时间、总耗时与缓存来源。
- 第一版不在界面展示供应商和模型，但数据库仍保存它们。

### 6.4 复制操作

每条完整记录提供：

- `复制译文`
- `全部复制`
- `使用当前设置重新翻译`

顶部标题栏现有复制按钮继续表示“复制译文”；“全部复制”位于记录内容操作区，不向标题栏增加第二个图标。

“全部复制”固定生成：

```text
完整原文

完整译文
```

复制规则：

- 不添加“原文：”“译文：”标签。
- 保留原文和译文内部换行、Markdown 与 LaTeX 源码。
- 不复制完成时间、耗时、缓存来源、模型、供应商或警告。
- 顶部和历史记录使用相同格式。
- 只复制原始文本，不复制 Markdown 渲染后的视觉文本。
- 只有完整成功记录可以复制。
- 历史正文尚未加载时，点击复制先按 `entryId` 读取正文；期间按钮显示 pending。
- 未完成译文与活动请求不能执行“全部复制”。
- 第一版不单独提供“复制原文”。

### 6.5 滚动规则

- 快捷键翻译、手动输入翻译和历史重新翻译开始时，只滚动到顶部一次。
- 阶段进度、耗时计时和流式增量不得持续抢夺滚动位置。
- 展开或折叠历史不强制滚动到顶部。
- 显示恢复且没有新请求时保留当前运行期的滚动位置。
- 打开设置再返回翻译页时保留滚动位置。
- 启动恢复历史时默认位于顶部最新译文。
- 清空成功后进入 idle 并滚动到顶部。

## 7. 历史数量配置

### 7.1 配置值

设置项名称为“最多保留翻译历史”，规则为：

```text
预设值：5、10、15、20
允许自定义：1～20 的整数
默认值：5
最大值：20
```

- N 是持久化数据库中的翻译记录总数，包括顶部最新译文。
- 用户可以选择预设值，也可以直接输入自定义整数，例如 3、8、17。
- 空值、非整数、小于 1 或大于 20 时显示字段错误并禁止保存。
- 不静默取整、截断或自动修正输入。
- 配置缺失时使用 5。
- 旧配置读取到非法值时运行时回退为 5，并在下次保存配置时写回。

### 7.2 生效与淘汰

- 配置保存成功后，立即从最旧记录开始删除，直到满足新的 N。
- 配置保存失败时，不改变历史模块当前采用的上限，也不执行淘汰。
- 将较大值改为较小值不弹二次确认；设置字段提示减少数量会立即移除超限旧记录。
- 将较小值改大不会恢复已经淘汰的记录。
- 每次新记录写入时，在同一数据库事务中完成写入和超限淘汰。
- 写入与淘汰提交后，数据库记录数不得超过 N。
- 启动时再次执行限额修复，以处理异常退出或旧状态。
- 限额收缩失败不回滚已经成功保存的配置，但必须显示警告；后续启动和写入继续尝试。

### 7.3 计数显示

历史区域标题显示：

```text
翻译历史 3 / 5
```

- 分子是当前持久化记录总数，包括顶部最新译文。
- 活动请求和尚未保存的临时成功结果不计入分子。
- 历史写入、淘汰、配置变更或清空成功后立即更新。
- 不增加历史详情弹窗，也不在计数区域显示数据库路径、大小或故障状态。

## 8. 清空翻译历史

### 8.1 入口与确认

- 主界面“翻译历史”标题行右侧放置 `Button variant="danger" size="sm"`，文字为“清空历史”。
- 不把清空按钮塞入应用标题栏。
- 数据库没有记录时不显示历史区域和清空按钮。
- 只有一条顶部最新译文时仍显示历史区域和清空按钮。
- 点击后使用现有 UI Kit `ConfirmDialog`。
- 第一版不提供单条删除。

确认文案：

> 确定清空全部翻译历史吗？所有已保存的原文和译文都会删除，此操作不会清除翻译缓存。

### 8.2 与活动请求的关系

- 存在选区捕获、翻译、流式输出或重新翻译请求时，清空按钮禁用。
- 禁用提示为“翻译完成后可清空历史记录。”
- 清空历史不会取消活动请求。
- 禁用规则避免清空完成后活动请求立即重新写入一条记录。

### 8.3 清空语义

- 清空删除全部持久化翻译记录，包括顶部最新译文和下方历史。
- 清空不影响 L1/L2 翻译缓存、配置、登录状态或当前翻译后端。
- 删除必须在事务中原子完成。
- 删除事务失败时保留全部可见记录并显示错误。
- 删除提交成功后，前端立即清除记录并回到 idle。
- 提交后尽力执行 WAL 截断和 `VACUUM`。
- 后续空间维护失败不推翻已经成功的清空，只记录无敏感内容的日志。
- 不直接删除整个历史目录或数据库 schema。
- 清空不承诺存储介质级安全擦除，界面无需额外说明。

## 9. 历史重新翻译

### 9.1 请求行为

- 点击历史记录“重新翻译”后，该请求成为顶部活动请求。
- 使用当前目标语言、当前翻译后端、当前模型及当前其他翻译配置。
- 沿用现有 `Refresh` 缓存语义：绕过 L1/L2 缓存读取，完整成功后正常更新共享缓存。
- 不增加另一套请求代次，现有 latest-wins 是唯一并发控制者。
- 如果已有活动请求，新请求立即取得界面资格；旧请求即使迟到返回，也不能更新界面、缓存后置动作或历史。

### 9.2 原记录保护与替换

请求期间原历史记录保留在原位置：

```text
历史 B 点击重新翻译
→ 顶部显示 B 的活动请求
→ 历史 B 仍保留
→ 请求完整成功且新历史保存成功
→ 在一个事务中写入新 B、删除旧 B、执行 N 条淘汰
→ 新 B 成为顶部最新译文
```

- 请求失败、取消或被更新请求覆盖时，旧记录保持不变。
- 新译文生成成功但历史写入失败时，旧记录保持不变。
- 此时新译文作为临时成功结果显示在顶部，并提示未保存。
- 重新翻译完整成功后使用新的完成时间、来源、目标语言与耗时。
- 正常成功替换不会增加历史总数。

## 10. 与翻译缓存的隔离

翻译历史与缓存必须是两个独立模块、两个独立数据生命周期：

- 普通翻译继续执行现有 `L1 → L2 → 翻译后端` 查询链路。
- 历史数据库不参与缓存查询或缓存键生成。
- 缓存命中仍创建一条独立翻译记录。
- 历史重新翻译继续使用现有 `Refresh` 语义。
- 历史创建、替换、淘汰和清空不得修改或删除 L1/L2。
- 清除、重建、淘汰或版本失效缓存不得修改翻译历史。
- Prompt 或缓存键版本变化不能让历史记录失效。
- 历史写入失败不改变缓存写入结果。
- 缓存故障不阻止历史保存成功结果。
- 两者只共同消费一次完整成功的翻译结果，不互相调用。

不得将 L2 缓存表或 `cache.sqlite` 复用为历史存储。允许复用 SQLite worker、迁移模式、路径解析和错误处理等底层实现经验，但不能复用缓存业务语义。

## 11. 持久化架构

### 11.1 存储位置

```text
easyT_Data/
└── translation_history/
    ├── history.sqlite
    ├── history.sqlite-wal
    └── history.sqlite-shm
```

- 使用项目现有 `easyT_Data` 根路径解析。
- 不写入 Windows LocalAppData 等 C 盘应用数据目录。
- 不与 `cache.sqlite`、`config.json` 或 Qwen 凭证共用文件。
- 数据库直接明文保存，不加密、不增加隐私提示或设置开关。
- 日志禁止记录原文、译文、API Key、Cookie、Authorization 或完整模型响应。
- 卸载行为沿用项目现有 `easyT_Data` 策略，本需求不修改卸载流程。

### 11.2 TranslationHistory 深模块

Rust 后端新增独立 `TranslationHistory` 深模块。外部只通过窄 interface 使用：

```text
initialize(limit)
list_summaries()
get_entry(entry_id)
commit_entry(entry, replace_entry_id?)
clear_all()
apply_limit(limit)
```

该 interface 表示所需行为，具体 Rust 类型与命名可在实施设计中根据仓库规范调整，但职责不得外泄。

模块负责：

- SQLite 初始化、连接和专用 worker 生命周期。
- schema 版本及后续正常迁移。
- 记录写入、原子替换与 N 条淘汰。
- 稳定排序和摘要查询。
- 按 `entryId` 读取完整正文。
- 单条逻辑大小校验。
- 清空与尽力而为的磁盘维护。
- 数据库损坏隔离和空库重建。
- 将存储错误映射为历史领域错误。

模块不负责：

- 调用翻译后端。
- 判断 Qwen、Official API 或具体模型协议。
- 查询、更新或清除翻译缓存。
- latest-wins 请求代次。
- 页面展开状态、复制反馈或滚动位置。
- 创建登录窗口或读取敏感凭证。

Tauri Command 只负责参数校验、调用模块和错误映射，不实现排序、淘汰或替换规则。

### 11.3 前端状态 seam

不得把持久化历史数组和数据库状态塞进现有 `translationStore`。

```text
translationStore
├── 当前活动请求
├── latest-wins 资格
├── 流式译文
├── 阶段进度
└── 历史失败时的临时成功结果

translationHistoryStore
├── 初始化状态
├── 持久化摘要列表
├── 按需加载的完整正文
├── 展开状态
└── 清空、读取、复制和重新翻译的界面状态
```

- 两个 store 不互相直接调用。
- 翻译领域 controller 负责组合它们向页面暴露的小 interface。
- 页面不直接拼装数据库事务、淘汰或错误恢复规则。
- 历史正文折叠时卸载复杂渲染树，而不是删除持久化记录。

### 11.4 页面展示优先级

1. 存在活动请求：顶部显示活动请求。
2. 请求成功且历史保存成功：顶部显示持久化最新记录。
3. 请求成功但历史保存失败或内容超限：顶部显示临时成功结果及弱警告。
4. 无活动请求且存在历史：顶部显示历史中最新记录。
5. 都不存在：显示 idle。

## 12. 建议数据模型

实施设计应至少表达以下信息：

```text
TranslationHistoryEntry
├── entry_id                 稳定身份
├── sequence_id              数据库递增排序补充键
├── original_text            完整原文
├── translated_text          完整译文
├── original_summary         最多 160 Unicode 字符
├── translated_summary       最多 160 Unicode 字符
├── target_language
├── source_backend
├── source_provider
├── source_model
├── from_cache
├── total_elapsed_ms
└── completed_at_utc_ms
```

约束：

- 不保存 API Key、Cookie、Authorization Header、请求正文的第二份副本、推理内容或完整响应。
- 原文和译文是历史核心数据，各保存一次。
- 缓存命中时，来源元数据使用缓存结果记录的原始来源，不冒充当前配置中的模型。
- 完成时间是本次用户翻译行为完成并提交历史的时间，不使用缓存创建时间。
- `entryId` 用于界面引用；`sequence_id` 仅用于确定性排序，不暴露到界面。
- schema 必须带独立版本号，后续 schema 正常升级仍需迁移。
- “不迁移旧版翻译数据”不等于禁止未来历史数据库 schema 迁移。

## 13. 排序与时间

- 数据库存储 UTC Unix 毫秒时间戳。
- 排序固定为 `completed_at DESC, sequence_id DESC`。
- 系统时间回拨或多个记录时间相同，使用 `sequence_id` 保证确定顺序。
- 界面按当前 Windows 本地时区格式化：
  - 当天：`今天 14:32`
  - 昨天：`昨天 09:15`
  - 更早：`2026-08-12 18:40`
- Windows 时区变化后按新的本地时区展示，但数据库顺序仍由存储字段确定。
- 重新翻译成功形成新的完成时间，因此提升为顶部最新译文。

## 14. 加载与内存策略

### 14.1 启动加载

- 启动只加载最多 N 条轻量摘要。
- 最新记录默认展开，因此额外读取其完整正文。
- 其余记录展开时按 `entryId` 异步读取完整正文。
- 正文加载期间在对应记录局部显示 `Spinner`，不阻塞整个页面。
- 第一次加载成功后可以在当前运行时缓存完整字符串。
- 折叠时必须卸载 Markdown/KaTeX 渲染树。
- 删除、淘汰或清空后同步移除对应前端数据。
- 第一版无需分页或虚拟列表。

### 14.2 容量限制

- 废止此前针对内存会话历史提出的 5 MiB 总容量限制。
- 历史数据库不设置总字节容量限制，只按 N 淘汰。
- 单条记录逻辑大小上限为 2 MiB。

逻辑大小至少计算：

```text
原文 UTF-8 字节数
+ 译文 UTF-8 字节数
+ 摘要和少量元数据字节数
```

- 恰好 2 MiB 允许保存，超过则不保存。
- 超限不能截断后保存，避免形成不完整历史。
- 翻译仍按成功展示，并提示“译文已生成，但内容过大，未保存到翻译历史。”
- 该限制只属于历史模块，不复用或修改缓存的 1 MiB 规则。
- 数据库读取时也校验单条大小；异常超限记录不得一次性送入前端。
- 2 MiB 上限不暴露为用户设置。

## 15. 翻译完成与历史保存阶段

翻译完整返回后，最终成功顺序为：

```text
翻译后端或缓存返回完整结果
→ 按现有规则处理翻译缓存
→ 发布“正在保存翻译历史…”阶段
→ 历史写入或原子替换
→ 返回持久化 entryId 或非阻断历史警告
→ 前端进入最终成功状态
```

规则：

- 历史持久化接入现有翻译请求阶段进度机制，不建立第二套进度系统。
- 历史 SQLite 操作使用后台 worker，不阻塞 UI 线程。
- 历史保存独立短超时固定为 2 秒。
- 总耗时包含历史持久化等待，因为用户在最终成功展示前确实等待了该阶段。
- 缓存命中也需要新增历史记录，因此可能出现极短的保存阶段。
- 前端取得稳定 `entryId` 后再正式插入持久化历史列表。
- 不采用“先显示成功、后台静默保存”，避免退出时的不可解释丢失竞态。
- 历史保存失败或超时不回滚缓存，也不把完整翻译改为失败。

## 16. 错误分类与恢复

### 16.1 写入或读取失败

- 翻译结果继续按成功展示。
- 对应临时成功结果显示非阻断警告：“译文已生成，但未能保存到翻译历史。”
- 临时结果保留在当前内存顶部，应用退出后可能丢失。
- 后续翻译继续尝试写入，不自动无限重试当前记录。
- 历史失败不能改变缓存结果、latest-wins 或翻译成功语义。
- 启动时历史不可用，应显示一次弱提示，但应用仍可进入降级后的正常翻译状态。
- 日志只记录错误分类、数据库状态和路径，不记录正文。

### 16.2 数据库损坏或不兼容

- 正常旧 schema 应通过版本迁移升级。
- 损坏或无法支持的结构必须将数据库重命名隔离，并创建新的空库。
- 隔离文件名示例：`history.sqlite.corrupt-20260813-143205`。
- WAL/SHM 必须一并处理，避免旧状态混入新库。
- 不自动删除隔离文件。
- 不尝试从 L1/L2 缓存重建历史。
- 启动显示一次非阻断警告：“翻译历史存储异常，已创建新的历史记录库。”
- “清空历史”只作用于当前有效数据库，不删除隔离文件。
- 第一版不提供隔离文件恢复或删除界面。

## 17. UI Kit 扩展

本需求会修改翻译页和设置页，必须遵守 `docs/UI-Kit需求与架构共识文档.md`。新增两个 UI module，不新增依赖。

### 17.1 Combobox

`Combobox` 表示既可以从小规模候选中选择、也可以直接输入自定义值的通用控件。它不替换现有原生 `Select`。

建议 interface：

```ts
interface ComboboxOption {
  value: string;
  label: string;
}

interface ComboboxProps {
  value: string;
  options: ComboboxOption[];
  onValueChange(value: string): void;
  placeholder?: string;
  disabled?: boolean;
  required?: boolean;
  inputMode?: React.HTMLAttributes<HTMLInputElement>["inputMode"];
}
```

模块负责：

- 输入框与候选列表。
- 点击展开、选择和关闭。
- 输入时过滤候选。
- `ArrowUp`、`ArrowDown`、`Enter`、`Escape` 键盘交互。
- `combobox`、`listbox`、`option` ARIA 关系。
- 高亮项、选中项、焦点与 disabled 状态。
- 与 `FormField` 的 ID、说明和 invalid 关联。
- 列表打开期间才注册外部点击监听，并在关闭或卸载时清理。
- 360×200 窗口内的列表尺寸和滚动约束。

模块不负责：

- 历史条数的 1～20 整数业务校验。
- 多选、异步搜索、分组、虚拟滚动或任意 JSX option。
- 替换所有普通 `Select`。

设置领域负责范围校验，并通过 `FormField` 展示错误。

### 17.2 Collapsible

`Collapsible` 是受控单折叠区域，不内置业务状态和互斥手风琴。

建议 interface：

```ts
interface CollapsibleProps {
  open: boolean;
  onOpenChange(open: boolean): void;
  title: ReactNode;
  summary?: ReactNode;
  children: ReactNode;
  disabled?: boolean;
  unmountOnClose?: boolean;
}
```

模块负责：

- 使用原生 `button` 作为触发器。
- 整个标题行可点击。
- 鼠标、Enter 和空格键操作。
- 自动设置 `aria-expanded`、`aria-controls` 和稳定内容 ID。
- 使用 Lucide Chevron 具名导入展示状态。
- 折叠时显示可选摘要。
- disabled、focus-visible 和 easyT 视觉 recipe。
- `unmountOnClose=true` 时卸载复杂内容。
- 尊重 `prefers-reduced-motion`。

限制：

- 默认不做高度动画，避免长篇内容测量与布局抖动。
- 不内置手风琴互斥、拖拽、嵌套层级样式或任意动画参数。
- 不读取 Zustand、不调用 Tauri Command，也不知道原文、译文或翻译历史。

建议文件：

```text
src/components/ui/
├── Combobox.tsx
├── Combobox.test.tsx
├── Collapsible.tsx
├── Collapsible.test.tsx
└── index.ts
```

## 18. 并发与 latest-wins

- 现有 latest-wins 继续是唯一翻译并发控制者。
- 历史模块不得维护另一套“请求代次”。
- 只有现有 active 请求可以提交历史。
- 被覆盖请求的后端 Future 应按现有机制尽可能中止。
- 旧请求迟到返回不得写入历史、删除替换目标或更新界面。
- 历史重新翻译期间原记录保留，只有新记录持久化事务成功后才替换。
- 清空按钮在活动请求期间禁用，从交互上消除清空与新写入竞态。
- 配置限额变更、记录写入和清空必须在历史模块的单一串行存储上下文中执行。

## 19. 迁移规则

- 新版本首次创建空的 `history.sqlite`。
- 不从升级前的当前译文、L1、L2、日志或 Qwen 网页对话构造历史。
- 不增加旧翻译数据迁移开关、一次性迁移代码或兼容入口。
- 新版本上线后产生的完整成功结果才进入历史。
- 历史数据库自身后续 schema 升级必须使用版本迁移机制。
