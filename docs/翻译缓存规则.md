# 翻译缓存规则

- 状态：已实现，自动验证完成，待人工发布验收
- 实现审计：`42cc000` 及 AUD-001/AUD-002 后续修复（2026-08-10）

架构依据：[L1-L2 需求与架构共识文档](./L1-L2需求与架构共识文档.md)

> 审计结论：运行期永久 SQLite 错误的 Degraded 状态转换，以及 Store/Touch 队列满失败计数均已修复并通过自动测试，当前实现符合本规则，详见 SDD 0.4。真实 Qwen/Official API 凭证 E2E 仍待发布负责人执行。清除确认采用应用内自适应 `alertdialog`，不依赖浏览器原生确认框。

## 1. 规则优先级

本文是实现和测试翻译缓存时的规则速查表：

1. 缓存不得影响正常翻译。
2. 清除后的旧请求不得重新填充缓存。
3. 只有完整成功译文可缓存。
4. 精确匹配优先于提高命中率。
5. 本文与架构共识冲突时，以架构共识为准并同步修正文档，不得自行猜测。

## 2. 策略映射

| 场景 | 前端参数 | 内部策略 | 读缓存 | 成功后写缓存 | 公开命中率 |
|---|---:|---|---:|---:|---:|
| 全局快捷键普通翻译 | `forceRefresh=false` | Use | 是 | 是 | 参与 |
| 手动输入普通翻译 | `forceRefresh=false` | Use | 是 | 是 | 参与 |
| 右上角重新翻译 | `forceRefresh=true` | Refresh | 否 | 是，覆盖 | 不参与 |
| 错误态重试 | `forceRefresh=true` | Refresh | 否 | 是，覆盖 | 不参与 |
| 测试连接 | 内部决定 | Bypass | 否 | 否 | 不参与 |
| Qwen `saveHistory=true` | 内部决定 | Bypass | 否 | 否 | 不参与 |
| 诊断请求 | 内部决定 | Bypass | 否 | 否 | 不参与 |

“快捷键”专指全局翻译快捷键（默认 `Ctrl+T`），不是右上角刷新按钮。

## 3. Use 查找规则

```text
输入校验
  → 规范化
  → 超限预检查
  → 生成 CacheKey
  → L1
  → L2（最多 50 ms）
  → 翻译后端
```

- L1 命中：返回完整结果、更新 L1 LRU、异步 Touch L2。
- L2 命中：返回完整结果、提升 L1、异步 Touch L2。
- 两层未命中或 L2 不可用：请求翻译后端。
- 缓存命中即使启用流式输出也一次性返回，不伪造 delta。
- L2 迟到响应丢弃，不能覆盖已经开始或完成的网络结果。

## 4. 写入规则

### 4.1 允许写入

必须同时满足：完整成功、译文非空、策略为 Use/Refresh、逻辑大小不超过 1 MiB、epoch 有效。

写入顺序为同步 L1、异步 L2 UPSERT。L2 失败不回滚 L1，不改变翻译成功。

### 4.2 禁止写入

- 流式 delta、reasoning。
- 未完成译文或部分回答。
- 取消、超时、网络中断、协议不匹配、业务错误。
- 空译文、Bypass、超限项。
- 清除前启动且完成时 epoch 已失效的请求。

### 4.3 覆盖

相同 CacheKey 只有一个全局条目。Refresh 成功或后续成功写入整体替换译文、backend/provider/model、生成/访问时间和大小字段；新版本 `hit_count` 从 0 开始。Refresh 失败保留旧条目不变。

## 5. CacheKey 规则

### 5.1 算法与材料

- BLAKE3 256-bit，输出 32 字节 BLOB。
- domain：`easyT.translation-cache`。
- 固定字段顺序、整数宽度和字节序；所有变长字段带长度前缀。

```text
domain
cache_key_version
prompt_version
normalized_source_text
trimmed_target_language
output_affecting_parameters
```

### 5.2 不参与键

翻译后端、供应商、base URL、模型、登录账号、Cookie/ticket、设备标识、快捷键/手动来源、流式开关、超时和网页历史开关均不参与。

### 5.3 版本

- Prompt 内容或格式要求改变：提升 `prompt_version`。
- 键编码、规范化或输出参数集合改变：提升 `cache_key_version`。
- 旧版本条目不主动删除，变为不可达后由容量 LRU 淘汰。

## 6. 规范化规则

| 输入 | 允许变换 | 必须保留 |
|---|---|---|
| 单行 | 去开头 BOM；去首尾 Unicode whitespace | 内部空白、大小写、标点、反斜杠 |
| 多行 | 去开头 BOM；CRLF/CR 转 LF | 首尾空白、缩进、空行、Markdown、代码块、LaTeX |
| 目标语言 | trim | trim 后的内容与大小写 |

禁止 lowercase、空白折叠、NFC/NFKC、Markdown 重排、公式规范化、代码格式化和模糊匹配。

## 7. 大小规则

```text
logical_size_bytes =
    32
  + normalized_source_text_bytes
  + target_language_bytes
  + translated_text_bytes
  + source_backend_bytes
  + source_provider_bytes
  + source_model_bytes
  + 256
```

- 字符串按 UTF-8 字节计算。
- 大于 1 MiB：不读写缓存，翻译照常。
- 等于 1 MiB：允许缓存。
- 预检查已确定超限时不查询 L1/L2。
- 超限计入 `oversized_bypasses`，不进入公开命中率。

## 8. L1 规则

| 项目 | 固定值 |
|---|---:|
| 总容量 | 10 MiB |
| 总条数 | 1,024 |
| 单条 | 1 MiB |
| 短文本定义 | 原文 UTF-8 ≤ 256 字节且无 LF |
| 短文本条数 | 768 |
| 长文本容量 | 7 MiB |
| 长文本条数 | 256 |

- 两个 `lru::LruCache` 由同一状态锁管理。
- 替换旧键前先扣除旧计量。
- 先满足分池限制，再满足全局限制。
- 全局超限时选择两个分池尾部 `access_tick` 最旧项。
- L1 淘汰不删除 L2。
- L2 提升重新检查 epoch 与容量。
- 锁内不 await、不 I/O、不复制/序列化大字符串。

## 9. L2 规则

| 项目 | 固定值 |
|---|---:|
| 数据库 | bundled SQLite / rusqlite |
| 路径 | `easyT_Data/cache/translation_cache.sqlite3` |
| 最大逻辑容量 | 256 MiB |
| 淘汰低水位 | 230.4 MiB |
| 最大条数 | 50,000 |
| 条数低水位 | 45,000 |
| 单条 | 1 MiB |
| 删除批次 | 最多 500 条 |
| Lookup 预算 | 50 ms |
| worker 队列 | 512 |
| worker 栈 | 512 KiB |
| Touch 定时 flush | 30 秒 |
| Touch 数量 flush | 256 个不同键 |
| WAL checkpoint 阈值 | 16 MiB |
| 退出等待 | 最多 1 秒 |

- 一个 worker 独占一个 Connection。
- Lookup/Store/Touch 队列满时跳过，不阻断翻译。
- Clear/Shutdown 可靠入队。
- Store/Touch 携带 epoch，旧 epoch 在 SQLite 执行前丢弃。
- LRU 为 `last_accessed_at_ms`、`generated_at_ms`、`cache_key` 升序。
- 无 TTL；普通淘汰不执行完整 VACUUM。
- 物理文件大小用于显示，逻辑大小用于淘汰。

SQLite 固定配置：

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA page_size = 4096;
PRAGMA cache_size = -2048;
PRAGMA busy_timeout = 2000;
PRAGMA wal_autocheckpoint = 1000;
PRAGMA auto_vacuum = INCREMENTAL;
```

## 10. 统计规则

```text
公开命中率 = (l1_hits + l2_hits) / (l1_hits + l2_hits + misses)
```

- 分母为 0 显示“—”。
- Refresh、Bypass、oversized 和内部失败不参与。
- L2 超时/错误后 Use 走网络：计 miss，并增加 `lookup_failures`。
- 统计跨重启持久化，清除时归零。
- 界面条目数只统计 L2。
- 磁盘占用统计 main、wal、shm 实际大小。

## 11. Touch 与 LRU

- L1/L2 命中都增加该键的访问时间与命中数。
- Touch 按 CacheKey 合并。
- 30 秒、256 个不同键、淘汰前、清除前、关闭前任一条件触发 flush。
- 崩溃允许丢失最近 30 秒 Touch/统计。
- 同时间戳时用生成时间和 CacheKey 保证确定性。

## 12. Clear 规则

清除 L1、L2 主库/WAL/SHM、隔离库、Store/Touch 队列、合并 Touch和全部统计。

1. 增加 epoch。
2. 同一 L1 锁内清条目和进程内统计。
3. worker 拒绝旧 epoch 命令。
4. 关闭 SQLite。
5. 删除数据库相关文件与隔离文件。
6. 创建新 schema 与空统计。
7. 完成后返回成功。

- 不使用 `DELETE + VACUUM`。
- 不取消翻译，但旧 epoch 结果不得缓存。
- 不删除设置、登录状态和 Qwen 网页对话记录。
- 不清空当前页面原文/译文。
- 成功后移除缓存来源提示，不自动翻译。
- 失败时 L1 为空、L2 Degraded，翻译继续。

## 13. 错误规则

| 错误 | 当前请求 | worker | 恢复 |
|---|---|---|---|
| BUSY/LOCKED/临时 I/O | 走网络 | Ready | 后续自然重试 |
| 队列满/Lookup 超时 | 走网络 | Ready | 后续自然重试 |
| 单条记录非法 | 删除并 miss | Ready | 无需用户操作 |
| CORRUPT/NOTADB/schema/迁移失败 | 走网络 | 尝试重建 | 隔离后新建 |
| 权限/磁盘/初始化永久失败 | 走网络，L1 可用 | Degraded | 用户重建或下次启动 |
| Store/Touch 失败 | 译文仍成功 | 按错误分类 | 内部统计 |

普通翻译不展示缓存错误。只有详情、清除和重建操作显示缓存错误。

## 14. 展示规则

命中提示固定为：

> 此译文来自本机缓存，点击“重新翻译”可使用当前模型刷新。

- 位于 `OriginalTextPanel` 与 `TranslationPanel` 之间。
- 不属于译文，不进入 Markdown/KaTeX，不复制、不计字数、不持久化。
- 新请求开始时清除旧 `fromCache`。
- Refresh 成功或清除成功后隐藏。

Refresh 失败且旧缓存译文仍显示时：

> 重新翻译失败，当前仍显示此前的本机缓存译文。

保留旧译文与来源提示，不覆盖缓存。没有旧缓存译文时按普通错误处理。

## 15. 缓存详情

设置页只显示“查看缓存详情”入口。模态弹窗显示：

- L2 条目数。
- 实际磁盘占用 / 256 MB。
- 公开命中率。
- 缓存路径。
- 本机存储说明。
- 清除按钮。

清除必须通过应用内 `alertdialog` 二次确认并在执行期间禁用。确认框必须适配窄屏：宽度受视口约束、内容超高时可滚动、操作按钮可换行且文字不被压缩。L2 Degraded 时显示不可用，并将操作改为“重建持久化缓存”。

## 16. 隐私规则

- 译文明文写 SQLite，不加密。
- 原文不落库，只保存哈希和原文字节数。
- 不记录 API Key、Authorization、Cookie、Qwen ticket、设备标识、请求正文或完整响应。
- 不创建额外缓存备份。
- 隔离文件随清除删除。
- 清除不是安全擦除。

## 17. 必测边界

- 单行与多行首尾空白规则不同。
- CRLF、CR、LF 多行键一致。
- Markdown 缩进、代码围栏、LaTeX 反斜杠不变。
- 相同原文不同目标语言不命中。
- 相同原文切换模型/供应商仍命中。
- prompt/key 版本变化后不命中旧项。
- Refresh 成功覆盖、失败保留。
- saveHistory 完全 Bypass。
- L2 超时、队列满、损坏、不可写不阻断翻译。
- 清除与在途请求并发时无迟到回填。
- L1/L2 容量边界、恰好/超过 1 MiB。
- 缓存提示不被复制，不进入 Markdown/KaTeX。
